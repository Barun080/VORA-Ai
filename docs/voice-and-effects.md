# ระบบเสียง (รับคำสั่งเสียง + เสียงพูด VORA) และเอฟเฟกต์ด้านหลังอวตาร — 8 พ.ย. 2569

ทดสอบบนเครื่องทดสอบ Linux (Chromium headless, SQLite สำเนาข้อมูลจริง, หุ่นจำลอง) — **ไม่มีไมโครโฟนจริงและเข้าถึงบริการเสียงภายนอกไม่ได้**
ไมโครโฟนทดสอบด้วยตัวจำลอง SpeechRecognition ที่ส่งเหตุการณ์ตามลำดับของ Chrome ส่วนเสียงพูดจากเซิร์ฟเวอร์ทดสอบด้วยตัวจำลอง (ไม่เรียก edge-tts จริงเลย)

## A. รับคำสั่งเสียง (Voice Input)

Pipeline เดิม (ไม่ได้เปลี่ยน): ปุ่มไมค์/Space → `startListening()` → `Listener` (Web Speech API ของเบราว์เซอร์ ไม่มี getUserMedia เสียง) → ข้อความ → `ask(text, "voice")` → `/api/chat` เดิม → `respond()` → `Speaker` → อวตารพูด

| # | Problem | Root Cause | Changed | Why |
|---|---|---|---|---|
| 1 | กดไมค์ใหม่หลังเกิดข้อผิดพลาด แล้วหน้าจอกลับเป็น "ว่าง" ทั้งที่ไมค์ยังรับเสียงอยู่ / ส่งข้อความรอบก่อนไปถามซ้ำได้ | ตัวจัดการ `onend/onerror/onresult` ของรอบฟังเก่า (Chrome ส่งช้าหลัง `abort()`) ไปแก้ค่าของรอบใหม่: ตั้ง `active=false`, ล้างตัวจับเวลาของรอบใหม่ และเรียก `onEnd/onFinal` | `voice.js` `Listener`: ทุกเหตุการณ์ตรวจว่าเป็นรอบปัจจุบันก่อน · รอให้รอบเก่าปิดเสร็จ (≤400ms) ก่อนเปิดรอบใหม่ | ทำซ้ำได้บนโค้ดเดิม: `{"uiState":"idle","newRecRunning":"started"}` → หลังแก้ `{"uiState":"listening",...}` |
| 2 | ปุ่ม/คลื่นเสียงแสดง "กำลังฟัง" ทันทีที่กด แม้ไมค์ยังไม่ทำงาน · ไมค์ค้างไม่เริ่ม = ค้างกำลังฟัง 12 วิ | ตั้งสถานะ listening ทันทีหลัง `rec.start()` ไม่รอ `onaudiostart` | `Listener` ส่ง `onAudioStart`/`onSpeechEnd` · หน้าจอมีสถานะย่อย starting → live → transcribing · ไมค์ไม่เริ่มใน 6 วิ = แจ้ง "ไมโครโฟนไม่ตอบสนอง" | ไม่ให้ผู้ใช้เข้าใจผิดว่าระบบกำลังฟัง |
| 3 | ไม่พบไมค์ / ไมค์ถูกโปรแกรมอื่นใช้ (`audio-capture`) หน้าจอเงียบ ไม่บอกอะไร | `onError` เดิมจัดการแค่ 4 รหัส | ข้อความเข้าใจง่ายทุกรหัส (ไทย/อังกฤษ) · สถานะ error 6 วิ แล้วกดใหม่ได้ทันที · บันทึกรหัสส่งหลังบ้าน (event `voice`) | |
| 4 | ตัวฟังการเปลี่ยนสิทธิ์ไมค์เพิ่มขึ้นเรื่อย ๆ | `checkMic()` สร้าง `PermissionStatus` + `onchange` ใหม่ทุกครั้ง แต่ละตัวเรียก `checkMic()` อีก | ใช้ `PermissionStatus` ตัวเดียว | Duplicate listener |

**ยังไม่ทราบอาการจริงบนเครื่องของทีม** — สาเหตุที่พบบ่อยบน Windows ซึ่งโค้ดแก้ไม่ได้: Web Speech API ของ Chrome ต้องใช้อินเทอร์เน็ต (`network`), สิทธิ์ไมค์ (`not-allowed`), ไมค์ถูกใช้ (`audio-capture`) — ตอนนี้ทุกกรณีขึ้นข้อความชัดเจน และ ⚙ ตั้งค่า → แถว "ไมโครโฟน / แปลงเสียง", "ข้อผิดพลาดล่าสุด" บอกรหัสจริง

ไม่ได้เปลี่ยน: API `/api/chat`, AI/RAG/Router, สัญญา Event, ระบบลำดับความสำคัญ (`InteractionManager`), กล้อง

## B. เสียงพูด VORA (TTS)

| | ก่อน | หลัง |
|---|---|---|
| ผู้ให้บริการ | `.env` = `VORA_TTS_PROVIDER=browser` → Chrome บน Windows มักมีแค่ "Microsoft Pattara" (ผู้ชาย) และรายการเลือกเสียงจัด Pattara ไว้ก่อนเสียงผู้หญิงอื่น | `edge` (edge-tts มีในโปรเจกต์และติดตั้งในเครื่องแล้ว ไม่มีค่าใช้จ่าย ไม่ต้องใช้ API key) |
| เสียง | ไทย Premwadee / อังกฤษ Ava (คนละคน) | **th-TH-PremwadeeNeural เสียงเดียวทุกภาษา** (`VORA_TTS_VOICE_EN=same`) — ข้อความไทยปนอังกฤษอ่านด้วยเสียงเดียว ไม่สลับกลางประโยค |
| จังหวะ | ค่าเริ่มต้น | `-5%` (≈0.95 เท่า), pitch `+0Hz`, เว้นจังหวะทีละประโยค |
| คำตอบยาว | ส่งทั้งข้อความเป็นคำขอเดียว **ตัดที่ 600 ตัวอักษร** | ทีละประโยค + ดาวน์โหลดประโยคถัดไประหว่างเล่น (เริ่มพูดเร็วขึ้น ไม่ถูกตัด) |
| ค้าง/ล่ม | ไม่มี timeout | เซิร์ฟเวอร์ 8 วิ/ประโยค · หน้าจอ 9 วิ · ล้ม = ไม่เรียกซ้ำ 60 วิ → เสียงเบราว์เซอร์ → ไม่มีเสียงเลยยังแสดงข้อความ |
| เสียงเงียบแต่ปากขยับ | ต่อเสียงผ่าน AudioContext ที่อาจถูกระงับ (autoplay) → ไม่มีเสียงออก | context ถูกระงับ = เล่นตรง ไม่ผ่านตัววิเคราะห์ · ตัววิเคราะห์ตัวเดียวทั้งหน้า |
| แคช | ไม่จำกัด | สูงสุด 800 ไฟล์ (คำทักทาย/ข้อความซ้ำใช้แคช) |

ตัวแปรใน `.env` (ไม่มีคีย์ลับ): `VORA_TTS_PROVIDER=edge`, `VORA_TTS_VOICE_TH`, `VORA_TTS_VOICE_EN=same`, `VORA_TTS_RATE=-5%`, `VORA_TTS_PITCH=+0Hz`, `VORA_TTS_TIMEOUT=8` — `.env` อยู่ใน `.gitignore` แล้ว
ฟังเสียงจริง: ⚙ ตั้งค่า → **ทดสอบเสียง VORA** (กดซ้ำ = ไทย → ไทยปนอังกฤษ → อังกฤษ) · ถ้าต้องการเสียงอังกฤษแยก ใส่ชื่อเสียงใน `VORA_TTS_VOICE_EN`

## C. เอฟเฟกต์ด้านหลังอวตาร (Holographic Core)

`frontend/kiosk/effects/HoloCore.js` + ส่วนท้าย `kiosk-reference.css` — HTML/SVG ขนาดเล็ก (~30 element) + CSS animation · ไม่มี canvas/WebGL/วงรอบ requestAnimationFrame ถาวร
ชั้น: แสงนุ่ม · Energy Core · ตารางพื้น + เส้นสแกน · หกเหลี่ยม · วงแหวนใหญ่แบ่งช่วง (หมุนช้า) · วงกลาง (หมุนสวน) · วงเล็ก (pulse) · วงสแกน · วงโคจรเอียง 2 วง · จุดข้อมูล 7 จุด + เส้นเชื่อม · อนุภาค 12 จุด — ทั้งหมดอยู่หลังอวตาร

ตามสถานะ: ว่าง = หมุนช้า · ฟัง = วงเล็ก pulse เร็ว (สีเขียว) · คิด = วงสแกน/จุดข้อมูลเร็วขึ้น (สีฟ้า) · พูด = วงแหวนขยาย/แสงเพิ่มตามระดับเสียง · ขัดข้อง = สีแดงจาง หมุนช้า
ระดับเสียง: ใช้ Event เดิม `AVATAR_MOUTH` (ค่าที่ `Speaker` ส่งให้ปากอวตารอยู่แล้ว) — **ไม่สร้างตัววิเคราะห์เสียงหรือเปิดไมค์เพิ่ม** ช่วงกำลังฟังจึงเป็น pulse คงที่ (Web Speech API ไม่ให้ระดับเสียงไมค์)
ธีมสว่าง: ความเข้ม 85% สีฟ้าโปร่ง + แดงอ่อน · ลดการเคลื่อนไหว: หยุดหมุน/อนุภาค/สแกน · ปิดได้: `kiosk-config.js → ui.holoEffects: false`

ประสิทธิภาพ (เครื่องทดสอบไม่มีการ์ดจอ วาดภาพด้วย CPU — ค่าเป็นเชิงเปรียบเทียบ): กล้องตรวจจับ 0.6–0.7 ครั้ง/วิ เท่ากันทั้งเปิด/ปิดเอฟเฟกต์ · long task เท่ากัน · อัตราเฟรมของหน้าจอลดจาก ~7 เป็น ~4 fps เมื่อเอฟเฟกต์เต็ม →
เพิ่ม **โหมดเบาอัตโนมัติ**: วัดเฟรม 3 วิ (หลังเริ่ม 10 วิ) ต่ำกว่า 30 fps = หยุดแอนิเมชันของเอฟเฟกต์ทั้งหมด → บนเครื่องทดสอบเปิด/ปิดเอฟเฟกต์ได้ ~7 fps เท่ากัน

## สิ่งที่ยังต้องทำบนเครื่องจริง

1. รีสตาร์ท `start.bat` (โหลดค่า `.env` ใหม่) แล้วกด ⚙ → ทดสอบเสียง VORA ฟังไทย / ไทยปนอังกฤษ / อังกฤษ
2. พูดกับไมค์จริง ถ้ายังมีปัญหา ดู ⚙ → "ข้อผิดพลาดล่าสุด" แล้วแจ้งรหัสนั้น
3. ดูอัตราเฟรมจริง: `document.querySelector('.hc').dataset.fps` ใน DevTools (ถ้ามี class `lite` = เครื่องช้าและลดเอฟเฟกต์แล้ว)
