### คำศัพท์ที่ใช้บ่อย (อธิบายสั้น) [อัปเดต 23 พ.ย. — ขยายเป็นหมวด]

**ก. ระบบทั่วไป**

| คำ | ความหมายแบบเข้าใจง่าย |
|---|---|
| **Kiosk (หน้าจอหุ่น)** | หน้าจอหลักของหุ่นยนต์ที่ผู้เข้าชมใช้ถาม-ตอบ |
| **Backend / API** | โปรแกรมฝั่งเซิร์ฟเวอร์ที่รับคำขอจากหน้าจอแล้วตอบกลับ — API คือ "ช่องทางสั่งงาน" ที่กำหนดรูปแบบไว้ |
| **Endpoint** | ที่อยู่ของคำสั่งหนึ่งใน API เช่น `POST /api/chat` = ส่งคำถาม |
| **Frontend** | ส่วนที่ผู้ใช้มองเห็นในเบราว์เซอร์ (หน้าจอหุ่น หลังบ้าน มือถือ) |
| **หลังบ้าน (Admin)** | หน้าเว็บสำหรับเจ้าหน้าที่ จัดการข้อมูล ตั้งค่า ดูสถิติ |
| **FastAPI / uvicorn** | เครื่องมือภาษา Python ที่ใช้สร้างเซิร์ฟเวอร์ของ VORA / ตัวรันเซิร์ฟเวอร์ |
| **PostgreSQL / SQLite** | ระบบฐานข้อมูล — PostgreSQL ใช้งานจริง, SQLite เป็นไฟล์เดียวใช้ทดสอบ/สำรอง |
| **Migration** | สคริปต์ปรับโครงสร้างตารางฐานข้อมูลอย่างเป็นขั้นตอน ย้อนกลับได้ |
| **`.env`** | ไฟล์ตั้งค่าของระบบ (มีรหัสลับ — ห้ามแชร์) |
| **Setting (ค่าตั้ง)** | ค่าที่ปรับพฤติกรรมระบบได้โดยไม่แก้โค้ด เช่น `VORA_FOLLOWUP=0` = ปิดถามต่อ |
| **WebSocket** | ช่องทางสื่อสารที่เปิดค้างไว้ ให้เซิร์ฟเวอร์ส่งข้อมูลมาที่หน้าจอได้ทันที (ใช้กับสมองโปร่งใส สถานะหุ่น) |
| **Session** | ช่วงการคุยของผู้ใช้หนึ่งคน ใช้แยกความจำของแต่ละคน |
| **Cache (แคช)** | ที่เก็บผลที่เคยคำนวณ/ดาวน์โหลดแล้ว เพื่อใช้ซ้ำได้เร็ว |
| **TTL** | อายุของข้อมูลที่จำไว้ หมดแล้วลบทิ้ง เช่น ความจำถามต่อ 180 วินาที |
| **Log** | บันทึกการทำงานของโปรแกรม ใช้ตรวจปัญหา |
| **Audit log** | บันทึกว่าเจ้าหน้าที่คนไหนแก้อะไรเมื่อไร ตรวจย้อนหลังได้ |
| **Gate / Phase** | ช่วงงานพัฒนาที่มีเกณฑ์ผ่านชัดเจน |
| **Backup (`_backups/`)** | สำเนาไฟล์เดิมก่อนแก้ เพื่อย้อนกลับได้ |

**ข. AI และการตอบคำถาม**

| คำ | ความหมายแบบเข้าใจง่าย |
|---|---|
| **Intent (เจตนา)** | ประเภทของคำถาม เช่น ถามค่าเทอม ถามการสมัคร |
| **Confidence (ความมั่นใจ)** | ตัวเลข 0–100% ว่าโมเดลมั่นใจแค่ไหนในเจตนาที่ทาย |
| **TF-IDF** | วิธีแปลงข้อความเป็นตัวเลข โดยให้น้ำหนักคำ/ตัวอักษรที่สำคัญมากกว่าคำที่พบทั่วไป |
| **n-gram ระดับตัวอักษร** | การตัดข้อความเป็นชิ้นละ 1–4 ตัวอักษร — ไม่ต้องตัดคำภาษาไทย |
| **Logistic Regression** | โมเดลจำแนกประเภทขนาดเล็ก ฝึกเร็ว ให้ค่าความน่าจะเป็น |
| **K-Fold / Cross-validation** | วิธีวัดความแม่นโดยแบ่งข้อมูลเป็นหลายส่วน สลับกันฝึก-ทดสอบ |
| **Accuracy / Macro-F1** | ตัวชี้วัดความแม่น — Macro-F1 ดูทุกเจตนาเท่ากัน ไม่เอียงไปหาเจตนาที่มีตัวอย่างมาก |
| **Training (การฝึกโมเดล)** | การปรับค่าน้ำหนักของโมเดลด้วยข้อมูลตัวอย่าง — ใน VORA มีเฉพาะโมเดลจำแนกเจตนาและโมเดลจำแนกป้าย ซึ่งเป็นโมเดลขนาดเล็กที่ฝึกในเครื่อง |
| **ฐานความรู้ (Knowledge Base, KB)** | คลังคำถาม-คำตอบ ข่าว สาขา ที่เจ้าหน้าที่อนุมัติแล้ว |
| **RAG (Retrieval-Augmented Generation)** | วิธีที่ "ค้นข้อมูลจากฐานความรู้ก่อน แล้วค่อยให้ AI เรียบเรียงคำตอบจากข้อมูลนั้น" — **ไม่ใช่การฝึกโมเดล** |
| **Retriever / ดัชนี (Index)** | ตัวค้นฐานความรู้ / ตารางที่เตรียมไว้ให้ค้นเร็ว — แก้ข้อมูลแล้วสร้างดัชนีใหม่ |
| **Threshold (เกณฑ์ขั้นต่ำ)** | ค่าต่ำสุดที่ยอมรับ เช่น คะแนนความตรงต่ำกว่า 0.22 = ถือว่าไม่มีข้อมูล |
| **LLM** | โมเดลภาษาขนาดใหญ่ เช่น Gemini, Typhoon — VORA **เรียกใช้ผ่าน API ไม่ได้ฝึกเอง** ใช้เรียบเรียงภาษาเท่านั้น |
| **Provider (ผู้ให้บริการ AI)** | บริษัท/บริการที่ให้ LLM เช่น Google (Gemini), SCB 10X (Typhoon), Ollama (ในเครื่อง) |
| **Prompt** | ข้อความคำสั่งที่ส่งให้ LLM |
| **Query Router** | ตัวคัดแยกคำถามตั้งแต่แรก: ไม่ปลอดภัย / เกี่ยวกับวิทยาลัย / ความรู้ทั่วไป / ยังไม่ชัด |
| **Answer Guard (G1–G9)** | ตัวตรวจคำตอบของ AI 9 ข้อ ว่าไม่แต่งชื่อ ตัวเลข วันที่ เบอร์โทร ฯลฯ ที่ไม่มีในข้อมูล — ไม่ผ่านใช้คำตอบจากฐานความรู้แทน |
| **Hallucination (AI แต่งข้อมูล)** | AI ตอบสิ่งที่ไม่มีจริงอย่างมั่นใจ — สิ่งที่ Router/RAG/Guard ช่วยลด |
| **Prompt injection** | ความพยายามสั่งให้ AI ลืมคำสั่งเดิม/ทำสิ่งไม่ควร — Router ปฏิเสธก่อนถึง AI |
| **Canary** | รหัสลับที่ฝังในคำสั่งระบบ ถ้าโผล่ในคำตอบแปลว่าคำสั่งรั่ว (Guard G7) |
| **PII / redact_pii** | ข้อมูลส่วนบุคคล (เบอร์โทร เลขบัตร อีเมล) / การปิดบังข้อมูลนั้นก่อนส่งออกนอกเครื่อง |
| **Answer contract** | ป้ายที่ทุกคำตอบต้องมี: มาจากไหน (`answer_source`), ตรวจระดับไหน (`verification`), ข้อความแจ้ง (`notice`) |
| **Trace (สมองโปร่งใส)** | บันทึกขั้นตอนที่ AI ใช้คิดในแต่ละคำถาม แสดงเป็น 5 ขั้นในหลังบ้าน |
| **ถามต่อ (Follow-up)** | ถามสั้น ๆ ต่อจากคำถามก่อน เช่น "แล้วพรุ่งนี้ล่ะ" — ระบบเติมเป็นคำถามเต็มให้ |
| **Fallback** | ทางสำรองเมื่อทางหลักล้มเหลว |
| **Circuit breaker** | กลไก "ตัดวงจร" หยุดเรียกบริการที่ล่มซ้ำ ๆ ชั่วคราว |
| **RPM / Rate limit** | จำนวนครั้งต่อนาทีที่อนุญาต / การจำกัดจำนวนครั้ง (`VORA_LLM_RPM`) |
| **429 (โควตาเต็ม)** | รหัสที่ผู้ให้บริการตอบเมื่อเรียกถี่เกินโควตา |
| **Timeout / Budget** | เวลารอสูงสุดต่อครั้ง / เวลารวมทั้งหมดที่ยอมรอ AI ต่อหนึ่งคำถาม |
| **Typhoon** | LLM ภาษาไทยของ SCB 10X — ทีมใช้อยู่ (API ฟรี) |
| **Gemini** | LLM ของ Google — ตัวเดียวที่ค้นเว็บด้วย Google Search ได้ |
| **Ollama** | โปรแกรมรัน LLM ในเครื่องเอง ไม่ใช้เน็ต (ต้องเครื่องแรง) |
| **โหมดฐานความรู้** | โหมดตอนเน็ตล่ม: ตอบจากฐานความรู้ทันที ไม่เรียก AI ภายนอก |

**ค. เสียง ภาพ และหน้าจอ**

| คำ | ความหมายแบบเข้าใจง่าย |
|---|---|
| **TTS / STT** | Text-to-Speech (แปลงข้อความเป็นเสียง) / Speech-to-Text (แปลงเสียงเป็นข้อความ) |
| **Web Speech API** | ความสามารถฟังเสียงที่มากับเบราว์เซอร์ Chrome/Edge (ต้องใช้เน็ต) |
| **Stream (สตรีมเสียง)** | ส่งเสียงทีละชิ้น เริ่มพูดได้ก่อนสร้างเสียงเสร็จทั้งหมด |
| **Pinned TTS (เสียงเตรียมล่วงหน้า)** | ไฟล์เสียงที่สร้างเก็บไว้ก่อน ใช้พูดได้ตอนเน็ตล่ม |
| **Barge-in** | ผู้ใช้กดไมค์/พูดแทรกระหว่างหุ่นพูด → หุ่นหยุดพูดทันที |
| **Wake word (คำปลุก)** | คำเรียกให้หุ่นเริ่มฟัง เช่น "วอร่า" — ยังอยู่ในห้องทดลอง |
| **Avatar / Rig** | ตัวละครบนจอ / โครงชิ้นส่วนที่ทำให้ตัวละครขยับได้ |
| **MediaPipe** | ชุดโมเดลภาพของ Google ที่รันในเบราว์เซอร์ (ตรวจคน ท่ามือ แปลงภาพ) |
| **Embedding** | การแปลงภาพ/ข้อความเป็นชุดตัวเลข เพื่อเทียบความคล้าย — เก็บเฉพาะตัวเลข ไม่เก็บภาพ |
| **Transfer Learning** | ใช้โมเดลสำเร็จรูปแปลงภาพเป็นตัวเลข แล้วฝึกโมเดลเล็กต่อด้วยภาพไม่กี่ภาพ (สอนกล้องจำป้าย) |
| **Attract mode** | โหมดเรียกความสนใจตอนไม่มีคนใช้ |
| **QR / Deep link** | รหัสให้มือถือสแกน / ลิงก์ที่เปิดตรงไปหน้าที่ต้องการ เช่น `?program=` |

**ง. ความปลอดภัย**

| คำ | ความหมายแบบเข้าใจง่าย |
|---|---|
| **JWT / Token** | บัตรผ่านดิจิทัลหลังล็อกอินหลังบ้าน อายุ 12 ชั่วโมง |
| **Role (สิทธิ์)** | ระดับสิทธิ์ admin / editor / viewer |

| **SSRF** | การหลอกให้เซิร์ฟเวอร์เปิดที่อยู่ภายในเครือข่าย — ระบบเปิดเว็บกันไว้ |

| **LAN / Tunnel** | เครือข่ายเดียวกันในพื้นที่ / ช่องทางเปิดเครื่องในวงแลนให้เข้าจากอินเทอร์เน็ต |
| **HTTP / HTTPS** | การรับส่งเว็บแบบไม่เข้ารหัส / แบบเข้ารหัส |

## 0. สรุปภาพรวมสำหรับผู้อ่านเร่งด่วน

**VORA** คือระบบซอฟต์แวร์หุ่นยนต์ประชาสัมพันธ์ของวิทยาลัยเทคนิคน่าน (ประกวดประเภทที่ 7 หุ่นยนต์ประชาสัมพันธ์อัจฉริยะ ปี 2569) (src: รายละเอียด.txt)

สิ่งที่ระบบทำได้จริงในปัจจุบัน [VERIFIED จากโค้ด + ชุดทดสอบ]:

1. หน้าจอ Kiosk มีอวตาร์เต็มตัว ถาม-ตอบด้วยเสียงหรือพิมพ์ ภาษาไทย/อังกฤษ
2. AI ตอบจาก **ฐานความรู้ที่เจ้าหน้าที่อนุมัติแล้ว** (RAG) และบอกตรง ๆ เมื่อไม่มีข้อมูล แล้วบันทึกคำถามนั้นไว้ให้เจ้าหน้าที่
3. ใช้ LLM (ตั้งค่าปัจจุบัน: Gemini) เพื่อ "เรียบเรียง" คำตอบจากข้อมูลที่ค้นได้ — มีตัวตรวจคำตอบ (Answer Guard) และถ้า LLM ใช้ไม่ได้ ระบบยังตอบจากฐานความรู้ได้
4. โมเดลจำแนกเจตนา (TF-IDF + Logistic Regression) ที่ **ฝึกใหม่ได้จากหลังบ้าน**
5. กล้องตรวจว่ามีคนยืนหน้าเครื่องเพื่อทักทาย (ไม่รู้จำตัวบุคคล ไม่บันทึกภาพ) จำท่ามือ และจำป้ายสาขาที่เจ้าหน้าที่สอนได้
6. หลังบ้าน: ข่าว สาขา ฐานความรู้ การสมัคร ตารางประกาศ ผู้ใช้ สถิติ ชุดประเมิน ฝึกโมเดล
7. ประชาสัมพันธ์อัตโนมัติตามเวลา พร้อมกันรบกวน (quiet hours, จำกัดจำนวน/ชั่วโมง, กันซ้ำ)
8. มือถือผ่าน QR: ถามต่อ ดูสาขา ข่าว ให้คะแนน และหน้าพิมพ์ใบสมัคร
9. ชั้นเชื่อมต่อหุ่นยนต์ (VORA Robot Protocol v1) + ตัวจำลองหุ่นยนต์ — **ยังไม่ได้ทดสอบกับบอร์ดจริง** [INFERRED จากเอกสาร: firmware เป็นตัวอย่างอ้างอิง]

## 7. โมเดลจำแนกเจตนา (Intent Classifier) — `ai/intent.py`, `ai/training.py`

[VERIFIED จากโค้ดและ docs/ai-model.md]
- คุณลักษณะ: TF-IDF ของ n-gram ระดับตัวอักษร 1–4 (`char_wb`) — ไม่ต้องตัดคำภาษาไทย
- ตัวจำแนก: Logistic Regression (C=12, class_weight=balanced)
- วัดผล: Stratified K-Fold (k ≤ 5) → Accuracy, Macro-F1, ผลรายเจตนา, Confusion matrix, ประโยคที่ทายผิด
- เลือกแบบจำลองจากการเทียบ 5-fold CV บนข้อมูลชุดเริ่มต้น (src: docs/ai-model.md):

| คุณลักษณะ | ตัวจำแนก | Accuracy |
|---|---|---|
| char_wb 1-4 | Logistic Regression | 0.59 |
| char_wb 2-4 | Logistic Regression | 0.58 |
| word (PyThaiNLP newmm) 1-2 | Logistic Regression | 0.53 |
| char + word | Linear SVM | 0.58 |
| char 1-3 | Complement Naive Bayes | 0.57 |

> **ข้อควรระวังในการนำเสนอ:** ค่า 0.59 เป็นค่า CV ของ "ตัวจำแนกเจตนาเพียงอย่างเดียว" บนข้อมูลชุดเริ่มต้น — ไม่ใช่ความแม่นยำของระบบตอบคำถามทั้งระบบ เอกสารเดิมระบุว่าชุดถาม-ตอบผ่าน 20/20 เพราะระบบตัดสินจากหลายสัญญาณ (src: docs/ai-model.md) — ตัวเลข 20/20 เป็นข้อมูลรุ่นเก่า [INFERRED ว่าอาจเปลี่ยนหลังเพิ่มข้อมูล]; ค่า accuracy ปัจจุบันของโมเดลที่ active ให้ดูในหลังบ้าน > โมเดล [UNKNOWN ค่าปัจจุบัน]

- ทุกครั้งที่ฝึก: บันทึกไฟล์โมเดล ผลวัด ผู้ฝึก เทียบกับเวอร์ชันก่อน เปิดใช้/ย้อนกลับได้ (`model_versions`)

## 8. ระบบค้นคืนความรู้ (RAG) — `ai/retriever.py`

### 8.1 วิธีทำงาน [VERIFIED]
- ดัชนี: TF-IDF `char_wb` 2–4 บน FAQ ที่ **approved** + สาขาที่ **เผยแพร่** + ข่าวที่ **active**
- คะแนน = max(คะแนนจากคำถาม, 0.75 × คะแนนจากเนื้อหา) + 0.08 ถ้าหมวดตรงกับเจตนา + 0.25 ถ้าคำสำคัญตรง
- ดึง top-k = 4, เกณฑ์ปฏิเสธ 0.22 (`VORA_RETRIEVAL_THRESHOLD`) — ต่ำกว่านี้ถือว่า "ไม่มีข้อมูล"
- ถ้าความมั่นใจเจตนา ≥ 0.55 จะค้นซ้ำเฉพาะหมวดนั้น

### 8.2 RAG ≠ การฝึกโมเดล (สำคัญมาก)

| | อัปเดตฐานความรู้ (RAG) | ฝึกโมเดลใหม่ (Retrain) |
|---|---|---|
| ทำอะไร | เพิ่ม/แก้ข้อมูล แล้วสร้างดัชนีค้นหาใหม่ | ปรับค่าน้ำหนักโมเดลจากประโยคตัวอย่าง |
| ใช้กับ | FAQ, ข่าว, สาขา | โมเดลเจตนา, โมเดลจำแนกป้าย (vision) |
| ปุ่มหลังบ้าน | อนุมัติความรู้ / rebuild | ฝึกโมเดลเจตนาใหม่ / ฝึก vision ใหม่ |
| LLM (Gemini) | ไม่ถูกฝึก — แค่อ่าน context | ไม่ถูกฝึก — **VORA ไม่ได้ฝึก LLM** |
| หลักฐาน | `knowledge/rebuild`, เวอร์ชัน retriever | `model_versions` + ผล K-Fold |

## 10. ผู้ให้บริการ LLM (Provider Chain) — `ai/llm.py` (391 บรรทัด)

[VERIFIED จากโค้ด]
- รองรับ: gemini, openai, anthropic, typhoon, ollama (ollama = รันในเครื่อง)
- ตั้งค่าปัจจุบัน (.env): ผู้ให้บริการหลัก gemini รุ่น `gemini-3.5-flash-lite`, สำรอง gemini, timeout 12 วินาที, งบเวลารวม (`VORA_AI_BUDGET_S`) 22 วินาที, จำกัด 12 ครั้ง/นาที (`VORA_LLM_RPM`) [VERIFIED: .env อ่านเฉพาะชื่อคีย์และค่าที่ไม่ใช่ secret]
- **[อัปเดต 22 พ.ย.] สวิตช์เลือกโมเดลจากหลังบ้าน** (`ai/providers.py`): ค่าที่เลือกในหลังบ้านทับค่าใน .env ทันที — **ปัจจุบันทีมเลือก Typhoon** `typhoon-v2.5-30b-a3b-instruct` (API ฟรีของ SCB 10X ไม่ต้องใช้บัตร ราว 200 ครั้ง/นาที) เพราะติดปัญหาการซื้อ API ของ Gemini · ค่าเริ่มต้นรุ่น Typhoon ในโค้ดเปลี่ยนจาก v2.1-12b เป็น v2.5-30b-a3b · ตัวสำรองของ Typhoon ดูได้ในหน้า "เลือกโมเดล AI" [UNKNOWN จากเอกสารนี้]
- **[อัปเดต 22 พ.ย.] ข้อควรแก้:** `VORA_LLM_RPM=12` ใน .env เป็นตัวจำกัดของ VORA เองที่ตั้งไว้สำหรับโควตา Gemini — ถ้าใช้ Typhoon เป็นหลักควรปรับเป็นราว 150 แล้วรีสตาร์ต มิฉะนั้นเกิน 12 ครั้ง/นาทีจะตอบจากฐานความรู้แทน
- **[อัปเดต 22 พ.ย.] ความเร็วที่สังเกตได้:** Typhoon ตอบราว 8.5 วินาทีต่อครั้ง (สมองโปร่งใส 22 พ.ย.) ช้ากว่า Gemini Flash Lite
- **[อัปเดต 21 พ.ย.]** เน็ตล่ม → ไม่เรียกผู้ให้บริการทางอินเทอร์เน็ตเลย (`llm.reachable`) — ollama ในเครื่องยังใช้ได้
- **CircuitBreaker**: ล้มติดกันครบเกณฑ์ → เปิดวงจร หยุดเรียกชั่วคราว
- **RateWindow**: เมื่อเจอ HTTP 429 (โควต้าเต็ม) หยุดเรียก **ทุกผู้ให้บริการ** 30 วินาที
- ถ้าตั้งหลักเป็น none → ปิดสำรองด้วย (ระบบตอบจากฐานความรู้ล้วน)
- `LLMUnusable` → engine ถอยไปใช้คำตอบจากฐานความรู้
- คีย์ Gemini ส่งทาง header `x-goog-api-key`; ข้อความ error ถูก redact

ประวัติ (src: chat): ช่วง 11–12 พ.ย. เจอโควต้า Gemini ฟรีเต็มบ่อย (เช่น Flash Lite RPM 16/15) → เพิ่ม RateWindow/backoff และปรับ RPM ให้ต่ำกว่าลิมิต; Gate 6E-5B (6 พ.ย.) ทดสอบ Gemini จริงได้สถานะ "NEEDS DECISION" เพราะเจอ 503 (src: docs/gate6e5b-gemini-validation.md)

## 11. ค้นอินเทอร์เน็ต / เปิดเว็บไซต์ / ข้อมูลเรียลไทม์

### 11.1 ค้นเว็บ (`ai/web.py`) [VERIFIED]
- เรียกเมื่อผู้ใช้ขึ้นต้นเช่น "หาข้อมูล…", "ค้นหา…" (เพิ่ม 11 พ.ย. — src: chat)
- Gemini google_search grounding + Wikipedia ทำพร้อมกัน → กรองความเกี่ยวข้องด้วย bigram → สรุปเป็นกล่อง (สรุป + ประเด็น + แหล่งอ้างอิง)
- `speech_text` อ่านทั้งสรุปและประเด็นออกเสียง (แก้ตามคำขอ "ให้โวร่าอ่านออกเสียงทั้งหมด")
- ปิดบัง PII, cache 5 นาที, backoff เมื่อโควต้าเต็ม (`_quota_until`)
- คำตอบติดป้าย notice ว่ามาจากอินเทอร์เน็ต

### 11.2 เปิดเว็บไซต์ (`ai/sites.py`) [VERIFIED]
- ตรวจคำขอ "เปิดเว็บไซต์…", "ต้องการดูเว็บไซต์…" → หา URL ตามลำดับ: เว็บวิทยาลัย → ชื่อวิทยาลัยแบบคลาดเคลื่อน (SequenceMatcher ≥ 0.7) → โดเมนที่พิมพ์มา → รายการที่รู้จัก → Wikipedia → ให้ AI เสนอเว็บทางการแล้ว **ตรวจว่ามีจริง** (แก้บั๊ก AI แต่งโดเมนปลอม 12 พ.ย. — src: chat)
- `check()` ป้องกัน SSRF (ไม่ให้เปิด IP ภายใน), บล็อกเว็บผู้ใหญ่/การพนัน, ตรวจ X-Frame-Options/CSP ว่าฝังในหน้าได้ไหม; ถ้าฝังไม่ได้ แสดงภาพตัวอย่าง + QR แทน
- `related()` สำหรับ "เว็บไซต์เกี่ยวกับ X" → ค้นหาเว็บที่เกี่ยวข้องพร้อมสรุปสั้น
- หน้าจอแสดงใน `WebPopup` พร้อม QR ลิงก์ไปเว็บนั้น

### 11.3 ข้อมูลเรียลไทม์ (`ai/realtime.py`) [VERIFIED]
- สภาพอากาศจาก **Open-Meteo** (ฟรี ไม่ใช้คีย์) ตั้งพื้นที่ "น่าน"; เวลา/วันที่จากเครื่อง
- **[อัปเดต 22 พ.ย.]** ถามอากาศได้ **ทั้ง 77 จังหวัด** (ตารางพิกัดอำเภอเมืองในเครื่อง `ai/provinces.py` + ชื่อเล่น เช่น โคราช อยุธยา กทม หาดใหญ่ หัวหิน) และ **พยากรณ์พรุ่งนี้** · วันที่ "พรุ่งนี้/เมื่อวาน" ได้ · แก้บั๊ก "สาขาเครื่องปรับอากาศ" ถูกเข้าใจว่าถามสภาพอากาศ (หัวข้อ 32.5)

### 11.4 เกี่ยวกับวิทยาลัย (About popup) [VERIFIED, src: chat 11 พ.ย.]

## 23. การเชื่อมต่อหุ่นยนต์ (Robot Integration)

### 23.1 VORA Robot Protocol v1 [VERIFIED: robot/protocol.py, docs/robot-protocol.md]
- JSON 1 ข้อความต่อ 1 บรรทัด ผ่าน **Serial (USB/UART)** หรือ **WebSocket**
- คำสั่ง: `hello`, `status`, `move`, `turn`, `gesture`, `head`, `led`, `stop`, `estop_reset`, `hb`
- heartbeat ทุก 300 ms; **บอร์ดต้องหยุดเองถ้าไม่ได้ hb เกิน 1,000 ms** (WATCHDOG_MS)
- ขีดจำกัดฝั่งซอฟต์แวร์: ความเร็ว ≤ 0.6 (normalize), ระยะ ≤ 300 cm ต่อคำสั่ง (ไม่มีคำสั่ง "เดินไปเรื่อย ๆ"), หมุน ≤ 360°
- ท่าทาง 15 ท่า: idle, wave, bow, nod, shake, present, point_screen, point_direction, explain, think, happy, shrug, listen, dance*, spin* (*ต้องเคลื่อนฐาน)
- รหัสผิดพลาด: INVALID, BUSY, OBSTACLE, ESTOP, WATCHDOG, LOW_BATTERY, TIMEOUT, HW_FAULT, DISCONNECTED
- เหตุการณ์จากบอร์ด: obstacle_detected/avoided/blocked, estop_pressed, watchdog_stop, low_battery, hw_fault
- ข้อกำหนดฝั่งบอร์ด: หลบสิ่งกีดขวางที่ใกล้กว่า 45 cm ขณะเดินหน้า, ปุ่มหยุดฉุกเฉินแบบค้าง (latching)

### 23.2 ซอฟต์แวร์ [VERIFIED]
- `bridge.py` — ตัวกลาง คิวคำสั่ง สถานะ heartbeat ส่งเหตุการณ์ให้หน้าจอ
- `drivers.py` — serial / websocket / simulator (`.env` ปัจจุบัน: **simulator**)
- `simulator.py` — จำลองหุ่น รวมสิ่งกีดขวางและ e-stop (ใช้สาธิต/ทดสอบได้โดยไม่มีบอร์ด)
- หลังบ้าน > หุ่นยนต์: สั่งเดินหน้า/ถอย/เลี้ยว/ท่าทาง/หยุดฉุกเฉิน

### 23.3 สถานะจริง
- `firmware/vora_esp32/vora_esp32.ino` เป็น **ตัวอย่างอ้างอิง** สำหรับทีมฮาร์ดแวร์ [INFERRED: ไม่พบหลักฐานการคอมไพล์/ทดสอบบนบอร์ด]
- **ยังไม่มีหลักฐานการทดสอบร่วมกับหุ่นยนต์จริง** [UNKNOWN → ต้องทดสอบเมื่อทีมฮาร์ดแวร์พร้อม] — การเคลื่อนที่ทางกายภาพเป็นความรับผิดชอบร่วมกับทีมฮาร์ดแวร์ (ขอบเขตข้อ 2)

### 29.2 สถานะปัจจุบัน (อัปเดต 23 พ.ย. 2569)
ซอฟต์แวร์ต้นแบบใช้งานได้ครบฟังก์ชันหลักบนเครื่องพัฒนา Windows; ชุดทดสอบผ่าน (Windows 1020/1020 หลังงาน F; งานหลังจากนั้นผ่านบนเครื่องพัฒนา รอยืนยันบน Windows); หุ่นยนต์ใช้ตัวจำลอง; TTS ใช้ Google; **LLM ใช้ Typhoon ตามที่เลือกในหลังบ้าน** (.env ยังเป็น Gemini Flash Lite)

### 29.3 ข้อจำกัดสำคัญ
1. ต้องใช้อินเทอร์เน็ตสำหรับเสียง (STT/TTS), LLM, ค้นเว็บ — **[อัปเดต 21 พ.ย.]** ตอนเน็ตล่มยังตอบจาก KB และพูดด้วยเสียงที่เตรียมไว้ได้ แต่รับเสียงพูดไม่ได้
2. โควต้า Gemini ฟรีจำกัด (ช่วงทดสอบเคยเกิน RPM) — วันงานถ้าคนถามถี่อาจตกไปตอบจาก KB อย่างเดียว · **[อัปเดต 22 พ.ย.]** ทีมเปลี่ยนไปใช้ Typhoon (ฟรี ~200 ครั้ง/นาที แต่ช้ากว่า ~8.5 วินาที/ครั้ง) — ต้องปรับ `VORA_LLM_RPM` ให้เหมาะ
3. TTS Google ไม่เป็นทางการ; edge-tts ใช้ไม่ได้บนเครือข่ายวิทยาลัย
4. Answer Guard ไม่ป้องกันการแต่งข้อมูลได้ทั้งหมด (ข้อความเชิงคุณภาพ ฯลฯ)
5. ความแม่นยำเจตนาบน CV ชุดเริ่มต้น ≈ 0.59 (ตัวจำแนกอย่างเดียว) — ต้องเพิ่มตัวอย่างจากการใช้งานจริง
6. ยังไม่ทดสอบกับหุ่นยนต์จริง, firmware เป็นตัวอย่าง
7. ไม่มี wake word ในระบบหลัก
8. ความปลอดภัยเครือข่าย (HTTP, 0.0.0.0) · token ใน log แก้แล้ว 21 พ.ย. 2569
9. หน่วยความจำบทสนทนาสั้นและอยู่ใน RAM
10. ยังไม่มีหลักฐานการใช้งานจริง ≥ 3 หน่วยงาน (เกณฑ์ 6.2/6.3)
11. **[อัปเดต 22 พ.ย.]** ถามต่อเป็นกฎ + AI ช่วยเฉพาะเคสที่กฎไม่เข้าใจ (ช้าขึ้นเท่าเวลา AI 1 ครั้ง) · ไม่ต่อย้อนหลังเกิน 1 คำถาม · หมดอายุ 3 นาที
12. **[อัปเดต 22 พ.ย.]** หน้ามือถือผ่าน QR เปิดได้เฉพาะเครื่องที่อยู่เครือข่ายเดียวกับเซิร์ฟเวอร์ — วันงานต้องให้ผู้ชมต่อ Wi-Fi ของทีม (หรือใช้เครื่องของทีม) · การเปิดสู่อินเทอร์เน็ตต้องแก้การยืนยันหน้าจอหุ่น (ตัดสินจาก IP) ก่อน มิฉะนั้นทุกคนผ่าน tunnel จะได้สิทธิ์หน้าจอหุ่น

### 29.4 Roadmap ที่แนะนำ (เรียงตามความสำคัญต่อการประกวด)
1. ทดสอบร่วมกับบอร์ดหุ่นยนต์จริงตาม docs/robot-protocol.md (watchdog, e-stop, สิ่งกีดขวาง) และบันทึกวิดีโอหลักฐาน

4. นำไปทดลองใช้ ≥ 3 หน่วยงาน เก็บสถิติ/แบบประเมิน/หนังสือรับรอง
5. แผนสำรองเสียง/LLM วันงาน: hotspot มือถือ, ตรวจโควต้า, ทดสอบโหมดไม่มี LLM
6. ปิดช่องโหว่ HIGH (token ใน URL, เครือข่ายแยก/HTTPS)
7. แก้ test `test_reports_overview_and_csv` ให้ไม่ขึ้นกับลำดับ; อัปเดต README (ยังเขียน 46 กรณี)

9. **[อัปเดต 22 พ.ย.]** รัน `test.bat` บน Windows ยืนยันงาน 21–22 พ.ย. (คาด 1092) · ลอง Typhoon จริงกับคำถามต่อ · ปรับ `VORA_LLM_RPM` · กรอก "คำบรรยายแนะนำวิทยาลัย" ในหลังบ้าน (ตอนนี้ว่าง ทำให้ "แนะนำวิทยาลัย" ตอบผิดหัวข้อ) · เคลียร์คำถามที่ตอบไม่ได้ (21 ข้อ ณ 22 พ.ย.)
10. **[อัปเดต 22 พ.ย.]** (แผน) ถามกลับเมื่อไม่มั่นใจแทนการเดา, ระบบรหัสประจำเครื่องหน้าจอหุ่นเพื่อเปิดหน้ามือถือสู่อินเทอร์เน็ต, งานที่เหลือในแผนก่อนประกวด (ป้ายอัจฉริยะ, สอนวอร่า 30 วินาที, ทักทายภาษาเหนือ) ดู Project `claude/vora-todo-plan.md`

### 32.1 F — สาธิตไม่สะดุด (ทนเน็ตล่ม) (src: docs/feature-F-offline-resilience.md)

**ปัญหาเดิม:** เน็ตล่ม → ทุกคำถามรอ AI ภายนอกจนหมดเวลา (12–22 วินาที) แล้วจึงตอบจาก KB, เสียงพูดล้มแล้วเงียบ, ไม่มีทางรู้ว่าระบบอยู่สถานะไหน และพบบั๊กว่าช่วงพักหลังเสียงล้ม ระบบไม่เล่นแม้ไฟล์เสียงที่มีอยู่แล้ว

**ทำงานอย่างไร**
- `connectivity.py` ขอหน้า `generate_204` ของ Google ทุก 15 วินาที (ไม่ส่งข้อมูลผู้ใช้) · ล้ม 2 ครั้งติด = ออฟไลน์ · ตอนออฟไลน์ตรวจถี่ทุก 5 วินาทีเพื่อกลับเร็ว · หรือเจ้าหน้าที่เปิด "จำลองเน็ตล่ม" (admin, บันทึก audit, ค้างหลังรีสตาร์ต)
- **โหมดฐานความรู้:** `llm.py` ไม่เรียกผู้ให้บริการทางอินเทอร์เน็ต (ollama ในเครื่องยังใช้ได้) → ตอบจาก KB ทันที · เปิดเว็บ/ค้นเว็บ/อากาศ → ข้อความแจ้งคงที่ทันที (`OFFLINE_NET_REPLY`, provider = `offline`)
- **เตรียมเสียงล่วงหน้า (ไม่ต้องอัดเสียงเอง):** ปุ่ม "ตรวจรายการข้อความ" ให้เซิร์ฟเวอร์ถามระบบจริงในโหมดฐานความรู้บนธุรกรรมที่ย้อนกลับทั้งหมด (ไม่ทิ้งข้อความ/สถิติ) → ได้คำตอบที่จะพูดจริง (FAQ, สาขา, ข่าว, คำทักทาย 12 ประโยค, ประกาศ, ข้อความ Guide, ข้อความระบบ) → หลังบ้านแปลงข้อความด้วย `speechText()` ตัวเดียวกับหน้าจอหุ่น → ปุ่ม "เตรียมเสียงที่ยังไม่มี" สร้างไฟล์ด้วยเสียงเดิมของ VORA เก็บใน `data/tts_cache/pinned/` + `manifest.json` (ไม่ถูกลบตามขีดจำกัดแคช) · ตอนพูดหาไฟล์ใน pinned ก่อน → ทำงานได้แม้ไม่มีเน็ต · ข้อมูลตัวอย่าง: 174 ข้อความ รวบรวมใน 0.6 วินาที
- **หน้าจอหุ่น:** ป้าย "โหมดฐานความรู้ · ไม่มีอินเทอร์เน็ต", แถว "อินเทอร์เน็ต" ในสถานะระบบ, แจ้งผู้ใช้หนึ่งครั้ง, **ปุ่มคำถามยอดฮิต 6 ข้อ** (เพราะรับเสียงพูดไม่ได้), เน็ตกลับ = กลับโหมด AI เองไม่ต้องรีสตาร์ต
- แก้บั๊กลำดับการตรวจแคชเสียงในช่วงพัก

**API ใหม่:** `GET /api/net`, `GET /api/quick-questions` (สาธารณะ) · `GET /api/admin/offline/status` (viewer) · `POST /api/admin/offline/force` (admin) · `GET /api/admin/offline/phrases`, `POST /api/admin/offline/check`, `POST /api/admin/offline/pin` (editor) · `/api/health` เพิ่มฟิลด์ `net`

**วิธีใช้ก่อนวันงาน (ต้องมีเน็ต):** หลังบ้าน → ระบบ → สาธิตไม่สะดุด → "ตรวจรายการข้อความ" → "เตรียมเสียงที่ยังไม่มี" → สุ่มกด "ฟัง" → แก้คำตอบ/ข่าว/สาขาเมื่อไรให้ทำซ้ำ · วันก่อนประกวดทำอีกรอบ

**ข้อจำกัด:** ตอนเน็ตล่มรับเสียงพูดไม่ได้ (Web Speech API ต้องใช้เน็ต) → ใช้แตะ/พิมพ์ · เตรียมเสียงได้เฉพาะคำตอบตายตัว (คำตอบที่ AI เรียบเรียงใหม่ทุกครั้งเตรียมล่วงหน้าไม่ได้) · ถอดสายเน็ตจริงยังไม่ได้ทดสอบ · ไม่มี package ใหม่ ไม่มี migration

**ค่าตั้ง:** `VORA_NET_CHECK_S` (15; 0 = ปิด), `VORA_NET_CHECK_URLS`

### 32.2 แก้ log ปลอดภัย (src: docs/fix-log-safety-20261121.md)

- `app/logsafe.py`: ตัวกรอง log ปิดค่า `token=` / `access_token=` / `Bearer` เป็น `***` ใน log ของ uvicorn, vora, httpx → ปิดข้อค้นพบ HIGH (token หลังบ้านโผล่ใน log) ฝั่ง log
- ซ่อนบรรทัดตรวจเน็ตทุก 15 วินาที — แสดงเฉพาะตอนเน็ตล่ม/กลับมา (เหตุการณ์ `[network]`)
- ทดสอบกับ uvicorn จริง: token ปรากฏ 0 ครั้ง · ชุดทดสอบ 5 ข้อ
- ยังเหลือ: token ยังอยู่ใน URL ฝั่งเบราว์เซอร์ → หลังประกวดย้ายไปส่งทางข้อความแรกของ WebSocket

### 32.3 A — สมองโปร่งใส (src: docs/feature-A-transparent-brain.md)

**ทำอะไร:** ทุกคำถามที่หน้าจอหุ่น หน้าหลังบ้านแสดงทันทีเป็น 5 ขั้น (ค่อย ๆ ปรากฏ) — สีเขียว = ผ่าน · เหลือง = ระวัง · แดง = Guard ตีกลับ · เส้นประ = ไม่ต้องใช้ขั้นนั้น

| ขั้น | แสดง |
|---|---|
| 1 เข้าใจคำถาม | เจตนา + ความมั่นใจ 3 อันดับ, สาขาที่พบ, เส้นทาง Router, **ถามต่อจากคำถามไหน (อัปเดต 22 พ.ย.)** |
| 2 ค้นฐานความรู้ | รายการที่ค้นเจอ + คะแนนความตรง + เกณฑ์ขั้นต่ำ |
| 3 AI เรียบเรียง | ส่งข้อมูลกี่ชิ้น, เวลา, ผู้ให้บริการ, ใช้แคช, AI บอกข้อมูลไม่พอ, AI ล่ม |
| 4 Answer Guard 9 ข้อ | ตาราง G1–G9 ข้อที่ไม่ผ่านกรอบแดง |
| 5 ป้ายแหล่งที่มา | answer_source, ระดับการตรวจสอบ, เวลารวม |

พร้อมคำตอบที่ VORA พูดจริง, ประวัติ 20 คำถาม, ปุ่มเต็มจอสำหรับจอที่สอง

**ทำไม:** ตอบคำถามกรรมการ "AI แต่งคำตอบเองไหม" ด้วยการให้เห็นกับตา — Router/RAG/Guard/contract มีอยู่แล้วแต่มองไม่เห็น

**ทำอย่างไร:** engine เก็บขั้นตอนด้วย `contextvars` แยกต่อคำถาม (ผู้ใช้พร้อมกันไม่ปนกัน) → `res.trace` เป็นแอตทริบิวต์ ไม่อยู่ใน JSON → `brain.publish()` เก็บในหน่วยความจำ 30 รายการ และส่ง WebSocket topic `ai.trace` เฉพาะ role admin → หน้าหลังบ้านแปลงด้วย `describeTrace()` (ฟังก์ชันล้วน ทดสอบด้วย node) · `GET /api/admin/brain/recent` (viewer)

**ความปลอดภัย:** ไม่มี system prompt/canary/CONTEXT เต็ม · คำถามผ่าน `redact_pii` · ไม่ลงฐานข้อมูล · ส่งออกผิดพลาดไม่กระทบการตอบ · ปิด: `VORA_BRAIN_TRACE=0`

**ข้อจำกัด:** ยังไม่แสดงการจำภาพจากกล้อง/ทักทายอัตโนมัติ · สีแดงเกิดเฉพาะเมื่อ AI แต่งจริง (สัญญากรรมการไม่ได้ว่าจะเห็นทุกครั้ง) · ประวัติหายเมื่อรีสตาร์ต (ตั้งใจ)

**ตัวอย่างจริงจากเครื่องทีม (22 พ.ย.):** "แนะนำวิทยาลัยเทคนิคน่านหน่อย" → ขั้น 1 เหลือง (ไม่ทราบ มั่นใจ 18%), ขั้น 2 ตรงสุด 40% → ตอบเรื่องที่ตั้งแทนแนะนำวิทยาลัย — สาเหตุ: ช่อง "คำบรรยายแนะนำวิทยาลัย (ไทย)" ในหลังบ้าน → ตั้งค่า ยังว่าง (ระบบจับคำถาม about ได้ถูกแล้ว) → ทีมต้องกรอก

### 32.4 สวิตช์เลือกโมเดล AI (src: docs/feature-ai-model-switch.md)

**ทำไม:** ทีมติดปัญหาการซื้อ API ของ Gemini → ต้องสลับไปตัวที่ฟรีได้เร็วโดยไม่แก้ไฟล์/รีสตาร์ต · วันงานถ้าโควตาตัวหนึ่งหมดสลับได้ในไม่กี่วินาที

| ตัวเลือก | ค่าใช้จ่าย | หมายเหตุ |
|---|---|---|
| ตามไฟล์ .env (ค่าเดิม) | — | พฤติกรรมเดิม (Gemini `gemini-3.5-flash-lite` หลัก+สำรอง) |
| ไม่ใช้ AI ภายนอก | ฟรี | ตอบจากคลังความรู้ตรง ๆ ไม่แต่งข้อมูลแน่นอน · ความรู้ทั่วไป/แปลภาษาตอบไม่ได้ |
| **Typhoon (SCB 10X) — ที่ทีมใช้อยู่** | ฟรี ไม่ใช้บัตร | เก่งภาษาไทย · ~200 ครั้ง/นาที, ไม่ประกาศเพดานรายวัน (ข้อมูลจากเว็บรวมรายการ AI ฟรี ไม่ใช่หน้าทางการ — ตรวจก่อนวันงาน) · ข้อมูลการใช้งานถูกนำไปปรับปรุงโมเดล (คำถามปิด PII ก่อนส่ง) |
| Google Gemini | มีโควตาฟรี | ตัวเดียวที่ค้นเว็บด้วย Google Search ได้ |
| Ollama (ในเครื่อง) | ฟรี | ไม่ใช้เน็ต · ต้องติดตั้งและเครื่องแรงพอ · timeout อย่างน้อย 30 วินาทีอัตโนมัติ · หน้าจอตรวจว่าเปิดอยู่และมีโมเดลอะไร |
| OpenAI / Anthropic | ต้องซื้อ | เผื่ออนาคต |

**ทำอย่างไร:** โค้ดเดิมทุกจุดอ่าน `settings.llm_*` → สวิตช์เปลี่ยนค่าในหน่วยความจำ (ไม่แก้ engine) · ค่าที่เลือกเก็บใน settings คีย์ `ai_choice` (ไม่มีคีย์) โหลดตอนเริ่มระบบ · เปลี่ยนแล้วล้างแคชคำตอบ/รีเซ็ต circuit breaker · ปุ่ม "ทดสอบการเชื่อมต่อ" · API: `GET/POST /api/admin/ai/models` (ดู viewer / เปลี่ยน admin + audit), `POST /api/admin/ai/models/reload`

**ความปลอดภัย:** คีย์อยู่ใน `.env` เท่านั้น (`VORA_KEY_TYPHOON=…` ฯลฯ — กด "โหลดคีย์จาก .env ใหม่" ไม่ต้องรีสตาร์ต) · หน้าเว็บไม่รับ/ไม่แสดงคีย์ · ไม่อยู่ใน API/audit/ฐานข้อมูล (มีชุดทดสอบตรวจคีย์ปลอม) · ชื่อโมเดลตรวจรูปแบบ · ชุดทดสอบไม่อ่านคีย์จริง (`VORA_DOTENV_RELOAD=0`)

**ข้อจำกัด:** ค้นเว็บ "หาข้อมูล…" ด้วย Google Search ใช้ได้เฉพาะมี Gemini เป็นตัวหลักหรือสำรอง (ไม่มี = Wikipedia แล้วให้ AI สรุป) · Typhoon ช้ากว่า (~8.5 วินาที/ครั้ง) · ต้องปรับ `VORA_LLM_RPM` (ดูหัวข้อ 10)

### 32.5 ถามต่อจากคำถามก่อนหน้า + สภาพอากาศ 77 จังหวัด (src: docs/feature-followup-questions.md)

**ปัญหาเดิม (ทดลองจริง 22 พ.ย.):** "อากาศวันนี้" ✓ → "อากาศที่จังหวัดแพร่หล่ะ" ไปตอบด้วย AI ทั่วไป (ดูอากาศได้แค่น่าน) → "วันนี้" ตอบว่าไม่มีข้อมูล (จำได้แค่สาขา)

**ใช้กฎ (เร็ว < 1 ms ทำงานแม้ไม่มี AI):**

| หัวข้อก่อนหน้า | ถามต่อได้ | ผล |
|---|---|---|
| สภาพอากาศ | "ที่แพร่ล่ะ", "แล้วพรุ่งนี้ล่ะ", "วันนี้", "ฝนตกไหม" | อากาศจังหวัดนั้น/พยากรณ์พรุ่งนี้ (จำจังหวัดล่าสุด) |
| วันที่ | "แล้วพรุ่งนี้ล่ะ", "เมื่อวานล่ะ" | วันที่พรุ่งนี้/เมื่อวาน |
| ข่าว | "ข่าวถัดไป", "อันที่สามล่ะ" | ข่าวลำดับนั้นจากชุดเดิม · หมดแล้วบอก "มีข่าวเท่านี้" |
| เรื่องของสาขา (ค่าเทอม/สมัคร/อาชีพ/เรียนอะไร/ทุน) | "แล้วไอทีล่ะ" | หัวข้อเดิมแต่เปลี่ยนสาขา |
| มีระดับชั้น | "ส่วน ปวส. ล่ะ" | สลับ ปวช./ปวส. |
| เรื่องอื่นจาก KB | คำสั้นที่ไม่ใช่คำถาม ("แล้วเทอม 2 ล่ะ") | ต่อท้ายคำถามเดิม (แม่นน้อยกว่า) |

**ให้ AI ช่วยเขียนคำถาม (เมื่อกฎไม่เข้าใจ):** ใช้เฉพาะคำถามสั้นที่ดูเป็นคำถามต่อ (มี "แล้ว/ส่วน/ล่ะ" หรือคำชี้แทน "อันนั้น ที่ว่า มัน เมื่อกี้ เพิ่มเติม…") → ส่งคำถามก่อนหน้า + คำตอบย่อ + คำถามล่าสุด (ผ่าน `redact_pii`) ให้ AI ที่เลือกไว้ **เขียนคำถามใหม่ 1 บรรทัด ไม่ได้ตอบ** → ค้น KB และผ่าน Guard ตามปกติ · ผลแปลก/AI ล่ม → ใช้คำถามเดิม · คำถามที่สั่งระบบ ("ลืมคำสั่ง…") ไม่ถูกส่งให้ AI · เช่น "สาขาไอทีเรียนอะไร" → "แล้วมีหอพักให้อันนั้นไหม" = "มีหอพักสำหรับสาขาไอทีไหม" · "หาข้อมูลดาวอังคาร" → "แล้วดาวพฤหัสล่ะ" = "หาข้อมูลดาวพฤหัส"

**กันเดา/กันปน:** คำถามประโยคเต็มไม่แตะ · หัวข้อเดิมไม่ใช่อากาศแต่ถาม "พรุ่งนี้ล่ะ" → ไม่ต่อ · ความจำแยก session หมดอายุ 3 นาที · ตอบไม่ได้ → จำว่าไม่มีคำตอบ · log เก็บคำพูดจริง · สมองโปร่งใสบอกว่าใช้ "กฎ" หรือ "AI ช่วยเขียนคำถามใหม่"

**สภาพอากาศ:** `ai/provinces.py` ตารางพิกัดอำเภอเมือง 77 จังหวัด + ชื่อเล่น + ชื่ออังกฤษ (ข้อมูลในเครื่อง ไม่ค้นทางเน็ต) · ชื่อที่เป็นคำทั่วไป ("เลย" "ตาก" "แพร่") นับเป็นจังหวัดเฉพาะเมื่อมีคำบอกสถานที่ ("ที่เลย" "จังหวัดตาก") · รองรับ "อากาศที่…/อากาศ<จังหวัด>/พรุ่งนี้…" · ไม่นับ "เครื่องปรับอากาศ/อากาศยาน" (แก้บั๊กเดิม) · ส่งออกไป Open-Meteo เฉพาะพิกัด · จังหวัดของสถานศึกษาใช้พิกัดเดิมจาก .env

**ค่าตั้ง:** `VORA_FOLLOWUP=1`, `VORA_FOLLOWUP_TTL_S=180`, `VORA_FOLLOWUP_LLM=1`

**ข้อจำกัด:** ไม่ต่อย้อนหลังเกิน 1 คำถาม · ส่วน AI ช่วยเขียนช้าขึ้นเท่าเวลา AI 1 ครั้ง (Typhoon ~8 วินาที) และใช้งบเวลารวมเดียวกัน — เกินงบตอบจาก KB · ทดสอบด้วย AI จำลอง ยังไม่ลองกับ Typhoon จริง · ยังไม่ดึงอากาศจังหวัดอื่นจากเน็ตจริง

### 32.8 สิ่งที่ทีมต้องทำต่อบนเครื่องจริง

1. รีสตาร์ตเซิร์ฟเวอร์ → `test.bat` (คาด 1092 ผ่าน)
2. สาธิตไม่สะดุด: เตรียมเสียง → สุ่มฟัง → กด "จำลองเน็ตล่ม" ดูหน้าจอหุ่น → ลองถอดเน็ตจริง
3. สมองโปร่งใส: เปิดเต็มจอบนจอที่สอง/โปรเจกเตอร์ ดูว่าอ่านได้จากระยะกรรมการ
4. เลือกโมเดล AI: ยืนยันตัวสำรอง · ปรับ `VORA_LLM_RPM` ถ้าใช้ Typhoon · กดทดสอบการเชื่อมต่อ
5. ถามต่อ: ลอง "อากาศวันนี้ → ที่แพร่ล่ะ → แล้วพรุ่งนี้ล่ะ" และ "สาขาไอทีเรียนอะไร → แล้วมีหอพักให้อันนั้นไหม" ดูในสมองโปร่งใส
6. กรอก "คำบรรยายแนะนำวิทยาลัย" และเคลียร์คำถามที่ตอบไม่ได้
7. วันงาน: เตรียมเครือข่ายเอง (ข้อ 5.12) — ฮอตสปอต/เราเตอร์ของทีม · ถ้าให้กรรมการสแกน QR มือถือ ต้องให้ต่อ Wi-Fi ของทีม (หรือยื่นเครื่องของทีม)
