# ฐานข้อมูล VORA (PostgreSQL)

VORA ใช้ **PostgreSQL 16** เป็นฐานข้อมูลหลัก และยังรองรับ **SQLite** เป็นทางสำรอง (ใช้อัตโนมัติเมื่อไม่ได้ตั้งค่า PostgreSQL)
โค้ดของระบบทำงานเหมือนกันทั้งสองแบบ ชุดทดสอบ 44 กรณีผ่านทั้งบน PostgreSQL และ SQLite

| | PostgreSQL (แนะนำ) | SQLite (สำรอง) |
|---|---|---|
| เหมาะกับ | ใช้งานจริง ผู้ใช้หลายคนพร้อมกัน ขยายหลายสถานศึกษา | สาธิตเร็วๆ เครื่องที่ติดตั้ง PostgreSQL ไม่ได้ |
| ข้อมูลอยู่ที่ | บริการ PostgreSQL บนเครื่อง (ฐานข้อมูลชื่อ `vora`) | ไฟล์ `data/vora.db` |
| เปิดดูข้อมูลด้วย | pgAdmin 4 (ติดตั้งมาพร้อมกัน) | DB Browser for SQLite |
| สำรองข้อมูล | `backup_db.bat` → ไฟล์ `.dump` | `backup_db.bat` → ไฟล์ `.db` |

## 1. ติดตั้งและเชื่อมต่อ (ทำครั้งเดียว)

**ก่อนเริ่ม:** ปิดหน้าต่าง `start.bat` ถ้าเปิดอยู่ และต่ออินเทอร์เน็ต

1. ดับเบิลคลิก **`setup_postgres.bat`** ในโฟลเดอร์ `C:\VORA_Robot`
   (เครื่องใหม่: `setup.bat` จะถามให้เอง ตอบ `Y`)
2. ถ้าเครื่องยังไม่มี PostgreSQL สคริปต์จะถาม *"ติดตั้ง PostgreSQL 16 ลงเครื่องนี้อัตโนมัติ?"* ให้ตอบ `Y`
   - ตั้ง **รหัสผ่านผู้ดูแล PostgreSQL** (ผู้ใช้ `postgres`) อย่างน้อย 8 ตัว — **จดเก็บไว้** ต้องใช้ตอนเปิด pgAdmin
   - Windows จะถามสิทธิ์ผู้ดูแลเครื่อง ให้กด **Yes** แล้วรอ 3-10 นาที
3. ถ้าเครื่องมี PostgreSQL อยู่แล้ว สคริปต์จะถามรหัสผ่านของผู้ใช้ `postgres` ที่ตั้งไว้ตอนติดตั้ง
4. สคริปต์จะทำต่อเองทั้งหมด:
   - สร้างผู้ใช้ `vora` (รหัสผ่านสุ่ม) และฐานข้อมูล `vora` กับ `vora_test`
   - เขียนค่าการเชื่อมต่อลง `.env` (ไฟล์เดิมสำรองเป็น `_backups\env\.env.bak-วันที่`)
   - ถามว่าจะ **ย้ายข้อมูลเดิมจาก `data\vora.db`** ไหม → ตอบ `Y` (ข่าว หลักสูตร ความรู้ ผู้ใช้ สถิติ ประวัติ ย้ายครบ และตรวจจำนวนแถวทุกตาราง)
5. เห็นข้อความ **"เสร็จแล้ว!"** → ดับเบิลคลิก `start.bat` ตามปกติ
6. ตรวจผล: หลังบ้าน > แดชบอร์ด > สถานะระบบ ต้องขึ้น **ฐานข้อมูล: พร้อม · PostgreSQL 16.x**

> รันซ้ำได้ปลอดภัย ไม่สร้างของซ้ำ และไม่เขียนทับข้อมูลใน PostgreSQL โดยไม่ถามก่อน
> ไฟล์ `data\vora.db` เดิมไม่ถูกลบ เก็บไว้เป็นสำรองได้

### ติดตั้งเอง (ถ้าการติดตั้งอัตโนมัติไม่สำเร็จ)

1. ดาวน์โหลด PostgreSQL 16 สำหรับ Windows จาก https://www.postgresql.org/download/windows/ (ตัวติดตั้งของ EDB)
2. ติดตั้งแบบค่าเริ่มต้น พอร์ต `5432` ตั้งรหัสผ่านผู้ใช้ `postgres` แล้วจดไว้ (ไม่ต้องเปิด Stack Builder ตอนจบ)
3. ดับเบิลคลิก `setup_postgres.bat` อีกครั้ง แล้วใส่รหัสผ่านนั้น

## 2. ใช้งานประจำวัน

ไม่มีอะไรต้องทำเพิ่ม PostgreSQL เป็นบริการของ Windows ที่เริ่มเองทุกครั้งที่เปิดเครื่อง
ถ้า VORA เริ่มก่อน PostgreSQL พร้อม ระบบจะรอให้เองสูงสุด 60 วินาที และถ้า PostgreSQL หยุดชั่วคราวระหว่างใช้งาน ระบบจะเชื่อมต่อใหม่เองเมื่อกลับมา

### เปิดดูข้อมูลด้วย pgAdmin 4

1. เปิดเมนู Start → **pgAdmin 4**
2. ครั้งแรกให้ตั้งรหัสผ่านหลักของ pgAdmin (คนละตัวกับฐานข้อมูลได้)
3. ด้านซ้าย: Servers → PostgreSQL 16 → ใส่รหัสผ่านของ `postgres`
4. Databases → **vora** → Schemas → public → **Tables**
5. คลิกขวาที่ตาราง → **View/Edit Data → All Rows**

ตารางที่ใช้บ่อย:

| ตาราง | เก็บอะไร |
|---|---|
| `news` | ข่าวประชาสัมพันธ์ |
| `programs` | สาขาวิชา |
| `knowledge` | ฐานความรู้ที่ AI ใช้ตอบ |
| `unanswered` | คำถามที่ระบบตอบไม่ได้ |
| `chat_sessions`, `messages` | ประวัติการสนทนา |
| `feedback` | คะแนนและความคิดเห็น |
| `users` | บัญชีเจ้าหน้าที่ (รหัสผ่านเก็บแบบเข้ารหัส) |
| `audit_log`, `system_events` | ประวัติการแก้ไขและเหตุการณ์ระบบ |

> **แก้ข้อมูลผ่านหน้าหลังบ้านเสมอ** การแก้ตรงในฐานข้อมูลจะข้ามขั้นตอนอนุมัติ ประวัติการแก้ไข และการอัปเดตดัชนีความรู้ของ AI
> ถ้าเผลอแก้ตาราง `knowledge` โดยตรง ให้ไปที่หลังบ้าน > ฐานความรู้ AI > ปุ่ม "สร้างดัชนีใหม่"

**ใช้ VS Code แทนได้:** ติดตั้งส่วนเสริม **PostgreSQL** (ของ Microsoft) หรือ **SQLTools + SQLTools PostgreSQL Driver** แล้วเชื่อมต่อ host `localhost` พอร์ต `5432` ฐานข้อมูล `vora` ผู้ใช้ `vora` รหัสผ่านดูได้จากบรรทัด `VORA_DATABASE_URL` ใน `.env` (ส่วนระหว่าง `vora:` กับ `@`)

## 3. สำรองและกู้คืนข้อมูล

| ต้องการ | ทำอย่างไร |
|---|---|
| สำรองตอนนี้ | ดับเบิลคลิก `backup_db.bat` → ได้ไฟล์ใน `_backups\database\vora-วันที่-เวลา.dump` (เก็บ 30 ไฟล์ล่าสุด) สำรองได้ขณะระบบทำงาน |
| ดูรายการไฟล์สำรอง | เปิด Command Prompt ในโฟลเดอร์ VORA แล้วพิมพ์ `backup_db.bat --list` |
| กู้คืน | **ปิด `start.bat` ก่อน** แล้วพิมพ์ `backup_db.bat --restore vora-20261028-181410.dump` → พิมพ์ `YES` ยืนยัน ระบบจะสำรองข้อมูลปัจจุบันเป็น `vora-before-restore-...` ให้ก่อนอัตโนมัติ |

แนะนำให้สำรองก่อนวันสาธิตทุกครั้ง และคัดลอกโฟลเดอร์ `_backups\database`, `data\uploads`, `data\models` ไปเก็บในแฟลชไดรฟ์หรือคลาวด์
ตั้งสำรองอัตโนมัติรายวันได้ด้วย Task Scheduler ของ Windows: สร้างงานใหม่ ให้รัน `C:\VORA_Robot\backup_db.bat`

### ตรวจไฟล์สำรอง (เพิ่ม 1 พ.ย. 2569)

`python scripts\verify_backup.py --latest` (หรือระบุชื่อไฟล์) — **ไม่แก้ไขฐานข้อมูลใด ๆ**
- PostgreSQL: `pg_restore --list` ต้องอ่านสารบัญได้ แล้วกู้แบบสตรีมออกมานับแถวทีละตาราง ต้องตรงกับฐานข้อมูลปัจจุบันทุกตาราง
- SQLite: `PRAGMA integrity_check` + นับแถวทุกตาราง
- บันทึก SHA-256 และผลตรวจไว้ใน `<ไฟล์>.verify.json` · ควรตรวจขณะปิด `start.bat`

### ปรับโครงสร้างฐานข้อมูล (Schema Migration) — `migrate.bat`

ใช้เมื่อติดตั้งโค้ดรุ่นใหม่ที่ต้องเพิ่มคอลัมน์ (`create_all` สร้างได้เฉพาะตารางใหม่ ไม่เพิ่มคอลัมน์ให้ตารางเดิม)

| คำสั่ง | ทำอะไร |
|---|---|
| `migrate.bat` | ดูสถานะ (ไม่แก้ไขอะไร) |
| `migrate.bat upgrade` | **ปิด `start.bat` ก่อน** → สำรอง → ตรวจไฟล์สำรอง → แก้โครงสร้างในทรานแซกชันเดียว → ตรวจว่าข้อมูลเดิมทุกตารางไม่เปลี่ยน (จำนวนแถว + md5) |
| `migrate.bat downgrade 0001` | ย้อนขั้น 0001 (พิมพ์ `YES`) → สำรอง + ตรวจ → ส่งออกข้อมูลในคอลัมน์ที่จะลบเป็น JSON → ลบคอลัมน์ → ตรวจข้อมูลอื่นไม่เปลี่ยน · ต้องติดตั้งโค้ดรุ่นก่อนกลับด้วย |

- ไฟล์สำรอง/ส่งออก/บันทึกอยู่ที่ `_backups\database\migrations\` (**ไม่ถูกลบอัตโนมัติ** ต่างจากไฟล์ของ `backup_db.bat` ที่เก็บ 30 ไฟล์ล่าสุด) · บันทึกทุกครั้งใน `migration-log.jsonl`
- ถ้าไฟล์สำรองไม่ผ่านการตรวจ / เซิร์ฟเวอร์ยังเปิดอยู่ / พบโครงสร้างที่ทำไปบางส่วน → หยุดทันทีโดยไม่แก้ฐานข้อมูล
- ถ้าเปิด `start.bat` ด้วยโค้ดรุ่นใหม่โดยยังไม่ได้ upgrade เซิร์ฟเวอร์จะหยุดพร้อมข้อความให้รัน `migrate.bat upgrade` (ไม่แก้ฐานข้อมูลเอง)

| ขั้น | วันที่ | การเปลี่ยนแปลง |
|---|---|---|
| 0001 | 1 พ.ย. 2569 | ตาราง `news` เพิ่ม `location` VARCHAR(255), `location_type` VARCHAR(16), `location_map_url` VARCHAR(500) — NULL ได้ทั้งหมด ไม่มีค่าเริ่มต้น ข่าวเดิมไม่ถูกแก้ |
| 0002 | 11 พ.ย. 2569 | ตาราง `programs` เพิ่ม `suits_th`, `suits_en`, `gallery` (TEXT) สำหรับพรีเซนเทชันสาขาบนหน้าจอหุ่นยนต์ — NULL ได้ทั้งหมด สาขาเดิมไม่ถูกแก้ · ย้อนกลับต้องย้อน 0002 ก่อน 0001 |
| 0003 | 12 พ.ย. 2569 | ตาราง `news` เพิ่ม `gallery` (TEXT) ภาพประกอบเพิ่มเติมของข่าว/ประกาศ บรรทัดละ 1 URL แสดงเป็นสไลด์ — NULL ได้ ข่าวเดิมไม่ถูกแก้ · ย้อนกลับต้องย้อน 0003 ก่อน 0002 |

## 4. ย้ายข้อมูล / กลับไปใช้ SQLite

สคริปต์ `scripts\migrate_db.py` ย้ายข้อมูลได้ทั้งสองทาง (ปิด `start.bat` ก่อน และรันหลัง `call .venv\Scripts\activate.bat`)

```bat
:: SQLite -> PostgreSQL (เหมือนที่ setup_postgres.bat ทำ)
python scripts\migrate_db.py
:: เขียนทับข้อมูลใน PostgreSQL ใหม่ทั้งหมด
python scripts\migrate_db.py --force
:: PostgreSQL -> SQLite (ไฟล์ใหม่)
python scripts\migrate_db.py --from postgresql+psycopg://vora:รหัส@localhost:5432/vora --to sqlite:///C:/VORA_Robot/data/vora-from-pg.db
```

**กลับไปใช้ SQLite ชั่วคราว** (เช่น ไปสาธิตบนเครื่องที่ไม่มี PostgreSQL): เปิด `.env` ใส่ `#` หน้าบรรทัด `VORA_DATABASE_URL=...` แล้วเปิด `start.bat` ใหม่ ระบบจะใช้ `data\vora.db`
ข้อมูลที่เพิ่มใน PostgreSQL จะไม่ตามไปด้วย ถ้าต้องการให้ตรงกัน ให้ย้ายด้วยคำสั่ง PostgreSQL -> SQLite ด้านบนก่อน

| ต้องการกลับไปเหมือนเดิมทันที | ใส่ `#` หน้า `VORA_DATABASE_URL` ใน `.env` แล้วเปิด `start.bat` ใหม่ (ใช้ `data\vora.db` เดิม) |

## 7. รายละเอียดทางเทคนิค

- ไดรเวอร์ `psycopg 3` ผ่าน SQLAlchemy 2 (`postgresql+psycopg://`), connection pool 10 + overflow 20, `pool_pre_ping` เชื่อมต่อใหม่อัตโนมัติ
- สร้างตารางอัตโนมัติตอนเริ่มระบบ (`create_all`) — การเพิ่มคอลัมน์ให้ตารางเดิมใช้ `scripts/migrate_schema.py` (`migrate.bat`) และ `backend/app/schema_guard.py` ตรวจตอนเริ่มระบบว่าทุกคอลัมน์ในโค้ดมีในฐานข้อมูล
- PostgreSQL เข้มงวดกว่า SQLite: ไม่รับข้อความยาวเกินขนาดคอลัมน์และอักขระ NUL ระบบจึงปรับข้อความให้พอดีก่อนบันทึกในทุกฐานข้อมูล เพื่อให้ทำงานเหมือนกัน
- ไฟล์โมเดล AI (`data/models`) และรูปที่อัปโหลด (`data/uploads`) ยังเก็บเป็นไฟล์ ไม่ได้อยู่ในฐานข้อมูล ต้องสำรองแยก
- ค่าที่เกี่ยวข้องใน `.env`: `VORA_DATABASE_URL`, `VORA_TEST_DATABASE_URL`
