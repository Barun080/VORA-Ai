## สรุป

เพิ่ม **แผนผังความรู้ (Knowledge Constellation)** — กราฟแบบโต้ตอบที่สร้างจาก **ความสัมพันธ์ที่มีอยู่ในฐานข้อมูลจริงเท่านั้น** ไม่ใช้ AI เดาความสัมพันธ์ ไม่ตัดคำ/แยกข้อความเอง และไม่เพิ่มตาราง

ตัวอย่างใน Master Prompt (Computer Technology → AI, IoT, Web, Game, Animation) **ไม่ได้ถูกสร้าง** เพราะไม่มีข้อมูลนี้ในฐานข้อมูล — เมื่อทีมเพิ่มสาขา/ข้อมูลจริงในหลังบ้าน กราฟจะแสดงตามนั้นเอง

## ความสัมพันธ์ที่ใช้ (backend/app/constellation.py)

| เส้น (relation_type) | จาก → ถึง | หลักฐานในข้อมูล |
|---|---|---|
| `offers_level` | วิทยาลัย → ระดับ | `programs.level` ของสาขาที่เผยแพร่ |
| `has_department` | ระดับ → แผนก | `programs.department` ภายในระดับนั้น |
| `has_program` | แผนก → สาขา | `programs` ที่ระดับ+แผนกตรงกัน |
| `leads_to` | สาขา → อาชีพ | `programs.careers_*` ของสาขานั้น (ทั้งข้อความ ไม่แยกเป็นหลายอาชีพ) |
| `has_topic` | วิทยาลัย → หมวดความรู้ | `knowledge.category` ของรายการที่ **อนุมัติแล้ว** |
| `contains` | หมวด → คำถาม-คำตอบ | `knowledge` ที่อนุมัติในหมวดนั้น |

- Node: `id, title, category, description, knowledge_reference` (+ `count`/`code`/`level`/`department`/`image` ตามชนิด) — `knowledge_reference` ชี้แถวในฐานข้อมูล เช่น `programs:1`, `programs:1.careers_th`, `knowledge:12`
- Edge: `source, target, relation_type`
- `insufficient`: Node ที่ข้อมูลไม่พอ (สาขาไม่มีอาชีพ/คำอธิบาย, คำถามไม่มีคำตอบ, ไม่ระบุระดับ/แผนก) → หน้าจอแสดง "ข้อมูลยังไม่เพียงพอ…" **และไม่สร้าง Node แทน**
- ข้อมูลปัจจุบัน: 45 Node, 44 Edge (สาขา 7, ระดับ 2, หมวดความรู้ 9, คำถาม-คำตอบ 14), `insufficient` ว่าง
- Endpoint ใหม่ `GET /api/constellation?lang=th|en` (อ่านอย่างเดียว ไม่ต้องเข้าสู่ระบบ — ข้อมูลเดียวกับที่ `/api/programs` และ AI ใช้อยู่แล้ว)

## หน้าจอ (frontend/kiosk/experience/ConstellationView.js)

- เข้าจากปุ่ม "ดูแผนผังความรู้" ในหมวด **วิทยาลัย** และ **สาขาวิชา** (โหมดนำเสนอ)
- แสดงทีละชั้น: Node ที่โฟกัสตรงกลาง + ลูกโดยตรงเป็นวงรอบ + เส้นเชื่อม SVG · **จำนวนต่อหน้าคำนวณจากพื้นที่จริง (6–12) ให้ Node ไม่ทับกัน** เกินนั้นแบ่งหน้า ("อีก n หัวข้อ")
- คลิก/แตะ Node = เจาะลึก · Breadcrumb · ปุ่มขึ้นหนึ่งชั้น · กลับหัวข้อหลัก
- แผงรายละเอียด: คำอธิบายจากฐานข้อมูล + แหล่งอ้างอิง (`knowledge_reference`) + ปุ่ม "ฟัง VORA อธิบาย" (สาขา → `openCard` เดิม) / "ถาม VORA" (คำถาม → AI เดิม)
- คีย์บอร์ด: ลูกศรวน, Enter เจาะลึก (โฟกัสกลับที่ Node กลาง), Backspace ขึ้นชั้น, Home กลับหัวข้อหลัก
- พื้นที่แคบ (< 640 px เช่น มือถือ) → แสดงเป็นรายการปุ่มเต็มความกว้าง · Reduced Motion ปิด Animation
- อวตารชี้ (`pointing`) เมื่อเปลี่ยนชั้น
- ภาษาอังกฤษใช้ชื่อภาษาอังกฤษจากฐานข้อมูล (ป้ายชื่อหมวดความรู้เป็นคำแปลชื่อหมวด ไม่ใช่ข้อมูลวิทยาลัย)

### ปัญหาที่พบและแก้ระหว่างทดสอบ
1. จอ 1600×900 กราฟแคบเกินไปเพราะแผงรายละเอียดอยู่ข้าง ๆ → กลายเป็นรายการ — ย้ายแผงรายละเอียดลงด้านล่าง กราฟใช้ความกว้างเต็ม
2. จำนวนต่อหน้าคงที่ 10 ทำให้บางจอทับกัน/บางจอแสดงไม่ครบ → คำนวณจากพื้นที่จริง (ตรวจการทับกันก่อนวาง)
3. ปุ่ม "อีก n หัวข้อ" ทับ Node ด้านล่าง → ย้ายออกมานอกพื้นที่กราฟ
4. เจาะลึกแล้วพื้นที่ยังเลื่อนค้าง มองไม่เห็น Breadcrumb → เลื่อนกลับบนสุดเมื่อเปลี่ยนชั้น

### พบระหว่าง Regression รอบสุดท้าย (แก้แล้ว)
5. **สถานะชั่วคราวของอวตาร (Phase 2) ถูกล้างเมื่อสลับ Idle/Active**: เดิมทุกการเปลี่ยนโหมดส่ง `AVATAR_HINT null` → สถานะชั่วคราว เช่น `thanking` ถูกตัดถ้าหน้าจอเข้าโหมดว่างพอดี — แก้ให้ส่งเฉพาะตอนเข้า/ออกโหมดนำเสนอ (Gate 2 ข้อ 5 ล้ม 1 ครั้งจากกรณีนี้)
6. **กด "หยุด" แล้ว VORA พูดประกาศต่อทันที** (ชุดทดสอบเดิม ข้อ 13b ล้ม 1 ครั้ง): ตัวจัดตารางประกาศข่าว (scheduler) ส่งข่าวความสำคัญ 5 เข้าคิวระหว่างที่ผู้ใช้สนทนา ข่าวความสำคัญ ≥ 4 ไม่ถูกพัก (ออกแบบไว้สำหรับข้อความด่วนของเจ้าหน้าที่) จึงถูกพูดทันที 0.4 วิหลังกดหยุด — ไม่ได้เกิดจาก Phase 1–4 (ตรวจจาก log เซิร์ฟเวอร์: `[scheduler] announce news:1` ก่อนการกดหยุด) แต่เป็นประสบการณ์ที่ไม่ดี → เพิ่มช่วงเงียบ 5 วิหลังผู้ใช้สั่งหยุด (ปุ่มหยุด / Esc / ท่ามือ ✋) คิวประกาศเลื่อนเวลา ไม่มีข้อความถูกทิ้ง · ปุ่ม "เริ่มบทสนทนาใหม่" ของเจ้าหน้าที่ไม่มีช่วงเงียบ (พบจากชุดทดสอบเดิมข้อ 9) · ไม่กระทบ `/api/robot/stop` (ยังส่งทันทีเหมือนเดิม)

## Known Issues
