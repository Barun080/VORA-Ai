# สวิตช์เลือกโมเดล AI จากหลังบ้าน

> จัดทำ 22 พ.ย. 2569 · สถานะ: **ทำเสร็จแล้ว** · ชุดทดสอบบน VM ผ่าน 1035 ข้อ (19 ข้อที่ไม่ผ่านคือ test_gate6e5a/6e5b ที่ต้องใช้ Python 3.12 — ไม่เกี่ยวกับงานนี้)
> **รอยืนยันบน Windows** (คาด 1054 = 1040 เดิม + งานนี้ 14)

## 1. ทำอะไร

เมนูใหม่ **ปัญญาประดิษฐ์ → เลือกโมเดล AI** ให้ผู้ดูแลระบบ (admin) เลือกได้ว่าตอนนี้ VORA ใช้ AI ตัวไหน "เรียบเรียงคำตอบ":

| ตัวเลือก | ค่าใช้จ่าย | หมายเหตุ |
|---|---|---|
| ตามไฟล์ .env (ค่าเดิม) | — | พฤติกรรมเดิมทุกประการ |
| ไม่ใช้ AI ภายนอก | ฟรี | ตอบจากคลังความรู้ตรง ๆ ไม่แต่งข้อมูลแน่นอน · คำถามความรู้ทั่วไป/แปลภาษาตอบไม่ได้ |
| Typhoon (SCB 10X) | **ฟรี ไม่ต้องใช้บัตร** | เก่งภาษาไทย · จำกัดราว 200 ครั้ง/นาที · ข้อมูลการใช้งานถูกนำไปปรับปรุงโมเดล (คำถามผ่านการปิดข้อมูลส่วนบุคคลก่อนส่งอยู่แล้ว) |
| Google Gemini | มีโควตาฟรี | ตัวเดียวที่รองรับค้นเว็บ "หาข้อมูล…" |
| Ollama (ในเครื่อง) | ฟรี | ไม่ต้องใช้เน็ต · ต้องติดตั้งและเครื่องแรงพอ · ตอบช้ากว่า |
| OpenAI / Anthropic | ต้องซื้อ | มีไว้เผื่อในอนาคต |

เลือกตัวหลัก + ตัวสำรองได้ · กด **"บันทึกและใช้ทันที"** มีผลทันทีไม่ต้องรีสตาร์ต · รีสตาร์ตแล้วยังจำค่าเดิม · มีปุ่ม **ทดสอบการเชื่อมต่อ**

## 2. ทำไมถึงทำ

- ทีมติดปัญหาการซื้อ API ของ Gemini — ต้องสลับไปใช้ตัวที่ฟรีได้เร็วโดยไม่ต้องแก้ไฟล์และรีสตาร์ต
- วันประกวด ถ้าโควตาตัวหนึ่งหมด เจ้าหน้าที่สลับได้ภายในไม่กี่วินาที (ช่วยเกณฑ์ 4.3 ไม่ค้าง/ไม่ต้องรีสตาร์ต)
- ใช้ตอบคำถามกรรมการ "ถ้าไม่มี Gemini ทำงานได้ไหม" ได้ด้วยการสาธิตจริง (เกณฑ์ 4.4 ไม่ได้พึ่ง API สำเร็จรูปตัวเดียว)

## 3. วิธีใช้ (ตัวอย่าง Typhoon ฟรี)

1. สมัครที่ `playground.opentyphoon.ai` → สร้าง API key
2. เปิดไฟล์ `C:\VORA_Robot\.env` เพิ่มบรรทัด `VORA_KEY_TYPHOON=คีย์ที่ได้` แล้วบันทึก
3. หลังบ้าน → เลือกโมเดล AI → กด **โหลดคีย์จาก .env ใหม่** (Typhoon จะขึ้น "มีคีย์แล้ว")
4. เลือก Typhoon (ตัวสำรองเลือก Gemini หรือไม่มี) → **บันทึกและใช้ทันที** → **ทดสอบการเชื่อมต่อ**
5. ถามที่หน้าจอหุ่น แล้วดูเมนู "สมองโปร่งใส" ขั้น AI เรียบเรียง ต้องขึ้นผู้ให้บริการ typhoon

## 4. ทำอย่างไร (หลักการ)

- โค้ดเดิมทุกจุด (engine, ค้นเว็บ, แปลภาษา, สถานะ) อ่านค่า `settings.llm_*` อยู่แล้ว → สวิตช์แค่ **เปลี่ยนค่าในหน่วยความจำ** ไม่ต้องแก้ engine
- ค่าที่เลือกเก็บในตาราง settings คีย์ `ai_choice` (ไม่มีคีย์ API) → โหลดตอนเริ่มระบบ · ค่าเสีย/คีย์หาย → กลับไปใช้ .env และบันทึกเหตุการณ์
- เปลี่ยนแล้วล้างแคชคำตอบและรีเซ็ตตัวพักวงจร เพื่อให้เห็นผลของโมเดลใหม่ทันที
- Ollama ได้เวลารอนานขึ้นอัตโนมัติ (อย่างน้อย 30 วินาที) · หน้าจอตรวจว่า Ollama เปิดอยู่ไหมและมีโมเดลอะไร

## 5. ความปลอดภัย

- **คีย์อยู่ใน .env เท่านั้น** — หน้าเว็บไม่รับ ไม่แสดง API ไม่ส่งออก audit ไม่บันทึก (มีชุดทดสอบตรวจคีย์ปลอมว่าไม่รั่ว)
- ดูสถานะ: สิทธิ์ viewer ขึ้นไป · เปลี่ยน/โหลดคีย์: admin เท่านั้น · ทุกการเปลี่ยนบันทึก audit
- ชื่อโมเดลตรวจรูปแบบ (กันพิมพ์คำสั่งแปลก ๆ) · เลือกผู้ให้บริการที่ไม่มีคีย์ → ปฏิเสธพร้อมบอกวิธีแก้เป็นภาษาไทย
- ชุดทดสอบไม่อ่านคีย์จริงจาก .env (`VORA_DOTENV_RELOAD=0` ใน conftest)

## 7. ข้อจำกัด

- ค้นเว็บ "หาข้อมูล…" ใช้ได้เฉพาะเมื่อมี Gemini เป็นตัวหลักหรือตัวสำรอง
- **ยังไม่ได้ทดสอบกับ Typhoon/Ollama จริง** (ทดสอบด้วยการจำลองการเชื่อมต่อ) — ทีมต้องลองด้วยปุ่มทดสอบหลังใส่คีย์ และฟังคุณภาพคำตอบภาษาไทยผ่านสมองโปร่งใส
- ข้อมูลโควตาฟรีของแต่ละเจ้าอาจเปลี่ยนได้ ตรวจสอบที่เว็บผู้ให้บริการก่อนวันงาน
- ไม่ว่าเลือกตัวไหน ความถูกต้องยังขึ้นกับคลังความรู้ — AI ทำหน้าที่เรียบเรียงเท่านั้น
