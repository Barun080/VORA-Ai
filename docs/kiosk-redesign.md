# VORA Robot Kiosk — ปรับปรุงหน้าจอ BLACK × YELLOW (31 ต.ค. 2569)

ปรับหน้าจอหุ่นยนต์ (`http://localhost:8000/`) ใหม่ทั้งหมดตามภาพ Reference บน **ระบบเดิม** — ใช้ API, WebSocket, AI, ระบบเสียง, MediaPipe, Robot Protocol และระบบหยุดฉุกเฉินชุดเดิม ไม่ได้สร้างระบบจำลองมาแทน

ภาพหน้าจอจริงจากการทดสอบอยู่ในโฟลเดอร์ [`kiosk-redesign/`](kiosk-redesign/)

## 1. วิธีเปิดใช้งาน

1. ดับเบิลคลิก `start.bat` เหมือนเดิม แล้วเปิด `http://localhost:8000/` (หรือ `kiosk.bat` เพื่อเต็มจอ)
2. **ครั้งแรก** เบราว์เซอร์จะถามสิทธิ์กล้อง ให้กด *อนุญาต* — Chrome จำสิทธิ์ของ `localhost` ไว้ ครั้งต่อไปกล้องจะเปิดเองทันทีโดยไม่ต้องกดอะไร
   - ถ้าเปิดด้วย `kiosk.bat` แล้วไม่เห็นหน้าต่างขอสิทธิ์ ให้เปิด Chrome แบบปกติที่ `http://localhost:8000/` กดอนุญาตหนึ่งครั้งก่อน (ใช้โปรไฟล์เดียวกัน)
3. ไมโครโฟนจะถามสิทธิ์ตอนกดปุ่มไมค์ครั้งแรก (การรับเสียงของ Chrome ยังต้องต่ออินเทอร์เน็ตเหมือนเดิม)
4. หน้าจอเข้า **โหมดว่าง** เองเมื่อไม่มีใครแตะ 15 วินาที (อวตารขยายใหญ่กลางจอ) แตะจอครั้งเดียวเครื่องมือกลับมา — ดูข้อ 7
5. เจ้าหน้าที่: ปุ่ม **เครื่องมือ** (มุมขวาล่าง) หรือแตะป้าย **กล้อง** ที่หัวจอ → ปิด/เปิดกล้อง, เข้าโหมดหน้าจอว่าง, เต็มจอ, ทดสอบการทักทาย, เริ่มบทสนทนาใหม่ และดูสถานะการตรวจจับ (Session, รหัสติดตามชั่วคราว)
6. ดีไซน์เดิมยังเปิดได้: `/pastel/` (ม่วงพาสเทล ก่อนครั้งนี้) และ `/classic/` (พิมพ์เขียว)

คีย์ลัดเดิมยังใช้ได้: `Space` = เริ่มฟัง, `Esc` = หยุดพูดและหยุดหุ่นยนต์

## 3. การทำงานที่สำคัญ

**สถานะระบบไม่มีค่าปลอม** — หัวจอจะขึ้น "ระบบพร้อมใช้งาน" เฉพาะเมื่อ WebSocket เชื่อมต่อ, ฐานข้อมูลตอบ `select 1` ได้ และโมเดล AI โหลดแล้ว ไม่เช่นนั้นขึ้น "ทำงานบางส่วน" หรือ "ขาดการเชื่อมต่อ" แถวหุ่นยนต์บอกชัดว่าเป็น "หุ่นจำลอง" เมื่อใช้ `VORA_ROBOT_DRIVER=simulator`

**ลำดับความสำคัญ** (`InteractionManager`): หยุดฉุกเฉิน > ทักทาย > สนทนา > ประกาศ > ว่าง
- การทักทายแทรกการประกาศข่าวได้ ข่าวที่ถูกพักจะกลับเข้าคิวและประกาศต่อหลังผู้เข้าชมออกไป (รอ 8 วินาที)
- **ข้อตัดสินใจที่ต่างจากลำดับตัวเลขเล็กน้อย:** การทักทายอัตโนมัติจะไม่ตัดคำตอบที่ VORA กำลังพูดกับผู้ใช้ เพราะมีคนใช้งานอยู่แล้ว การตัดกลางประโยคเพื่อทักทายจะเสียมารยาทกับคนตรงหน้า
- สิ่งที่ผู้ใช้สั่งเอง (พูด พิมพ์ แตะ) แทรกการทักทายหรือประกาศได้ทันที เหมือนการพูดแทรกที่ระบบเดิมรองรับ
- ข้อความด่วนจากเจ้าหน้าที่ (`say` ระดับ 4) ไม่ถูกพัก

**ผู้เข้าชม** (`VisitorTracker`): ทักครั้งเดียวต่อการเข้าชมหนึ่งครั้ง คนเดิมยืนอยู่ไม่ทักซ้ำ, ไม่เห็นใครเกิน 6 วินาที = ปิด Session, มีคูลดาวน์จาก `VORA_GREETING_COOLDOWN` กันการเข้าออกถี่ ๆ, หลายคนพร้อมกันทักแบบกลุ่ม ("สวัสดีค่ะทุกคน")

**ความเป็นส่วนตัว**: ภาพประมวลผลในเบราว์เซอร์เท่านั้น ไม่บันทึกวิดีโอ ไม่ส่งภาพออก ไม่สร้าง Face Embedding ไม่จดจำใบหน้า รหัสติดตามเป็นตัวเลขลำดับและล้างทุกครั้งที่ Session จบ ข้อความแจ้งผู้เข้าชมอยู่มุมซ้ายล่างของจอ

## 5. ข้อจำกัดที่ยังเหลือ

- **ยังต้องทดสอบบนเครื่องจริง** ตามตารางข้อ 4: คนจริงหน้ากล้อง ท่ามือจริง เสียงจริง ถอดสาย USB กล้อง สแกน QR ด้วยมือถือ และหุ่นจริง

- ตัวติดตามจับคู่ใบหน้าด้วยตำแหน่งเท่านั้น ถ้าคนเดินสลับตำแหน่งกันเร็ว ๆ รหัสติดตามอาจสลับกัน (ไม่กระทบการทักทาย เพราะนับเป็น Session เดียวกันจนกว่าพื้นที่จะว่าง) คนที่หันหลังหรือใส่หน้ากากอาจตรวจไม่พบ เพราะใช้การตรวจจับใบหน้า
- ไม่ได้ทดสอบบน PostgreSQL ผ่านเบราว์เซอร์ (หลังบ้านทดสอบบน SQLite) — รัน `test.bat` บนเครื่องของทีมเพื่อยืนยันกับ PostgreSQL
- อวตารปัจจุบันเป็นตัวจำลอง 2D (SVG) การเคลื่อนไหวเป็นแบบหมุนชิ้นส่วน ไม่ใช่ Live2D — อวตารจริงจาก PSD ใช้ระบบเดียวกันได้ตาม `frontend/kiosk/avatar/README.md` แต่ต้องวัดจุดหมุนจากภาพจริง
- หน้าจอออกแบบสำหรับจอแนวนอน 1366 px ขึ้นไป จอแคบกว่า 1100 px จะเรียงลงมาเป็นคอลัมน์เดียว (ใช้ได้แต่ไม่ใช่ประสบการณ์หลัก)
- ฟังก์ชัน `color-mix()` ใน CSS ต้องใช้ Chrome/Edge 111 ขึ้นไป


## 7. Smart Idle / Active + Avatar Focus Mode + สถาปัตยกรรม 3 Controller (เพิ่ม 31 ต.ค. 2569 รอบที่ 2)

สำรองไฟล์ก่อนแก้รอบนี้: `_backups/before-changes/2026-10-31_2030_before-idle-focus-mode/`

### 7.1 สถาปัตยกรรม — พัฒนาต่อจากของเดิม ไม่ได้เขียนใหม่ทับ

```
             ┌──────────────── core/event-bus.js (Event กลาง) ────────────────┐
             │                                                                 │
 UI Controller            Avatar Controller                 Camera & Visitor Controller
 idle-ui.js               avatar/AvatarController.js        camera/CameraVisitorController.js
 (ต่อยอดจากไฟล์เดิม)        (ต่อยอดจากไฟล์เดิม)                 (ชั้นบาง ๆ ครอบของเดิม ไม่ได้แก้ของเดิม)
 · Idle/Active            · ท่าทาง สีหน้า ฟัง/คิด/พูด/ทักทาย    · CameraManager.js  (วงจรชีวิตกล้อง)
 · Mouse/Touch/Keyboard   · กล่องคำพูด                          · shared/vision.js (MediaPipe ใบหน้า/ท่ามือ/ป้าย)
 · Idle Timer             · ขยายอวตารตามโหมดหน้าจอ               · VisitorTracker.js (Visitor Session)
 · ซ่อน/แสดงแผง+Animation                                         · ผู้เข้าชมใหม่ / กลับมาซ้ำ
             │                     ▲                                  │
             └─────────── app.js (ตัวประสานงานบทสนทนาเดิม) ───────────┘
                    /api/chat · /api/greet · WebSocket · voice.js (STT/TTS) · /api/robot/stop · คิวประกาศ
```

| Controller | ไฟล์ | ที่มา |
|---|---|---|
| UI | `kiosk/idle-ui.js` | ไฟล์ Idle/Active เดิมของโครงการ (ตอนนั้นไม่มีหน้าไหนใช้แล้ว) — คงตรรกะ `busy()`, กันสั่นจอสัมผัส, MutationObserver ไว้ แล้วจัดเป็นคลาส `UIController` |
| Avatar | `kiosk/avatar/AvatarController.js` | คลาสเดิม เพิ่ม `connect()` รับ Event, กล่องคำพูด, `setFocus()` ขยาย/ย่อ — ส่วนคำนวณท่าทางไม่ได้แก้ |
| Camera & Visitor | `kiosk/camera/CameraVisitorController.js` | ย้ายโค้ด `startCamera()` จาก `app.js` มาไว้ที่นี่ — **`CameraManager.js`, `VisitorTracker.js`, `shared/vision.js` ไม่ได้แก้แม้แต่บรรทัดเดียว** |
| Event กลาง | `kiosk/core/event-bus.js` | ไฟล์ใหม่ (เล็ก) |

**Event ที่ใช้:** `UI_ACTIVITY`, `UI_IDLE`, `UI_ACTIVE`, `UI_LANG`, `VISITOR_DETECTED`, `VISITOR_RETURNED`, `VISITOR_JOINED`, `VISITOR_LEFT`, `FACE_POSITION`, `CAMERA_STATUS_CHANGED`, `CAMERA_GESTURE`, `CAMERA_SIGN`, `GREETING_STARTED`, `GREETING_FINISHED`, `AVATAR_LISTENING`, `AVATAR_THINKING`, `AVATAR_SPEAKING`, `AVATAR_IDLE`, `AVATAR_CAPTION`, `AVATAR_GESTURE`, `AVATAR_EMOTION`, `AVATAR_ALERT`, `AVATAR_MOUTH` (รายละเอียดในไฟล์ `core/event-bus.js`)

ตัวอย่างการไหลของ Event (ตรวจลำดับจริงในการทดสอบข้อ 5b):
`VISITOR_DETECTED` (กล้อง) → app.js เรียก `/api/greet` → `GREETING_STARTED` → `AVATAR_SPEAKING` (อวตารโบกมือ พูด แสดงกล่องคำพูด) → `GREETING_FINISHED` → `AVATAR_IDLE`
— หน้าจอยังอยู่ในโหมด Idle ตลอด เพราะการเห็นคนอย่างเดียวไม่ใช่ UI_ACTIVITY

**ทำไม app.js ยังอยู่:** เป็นตัวประสานงานบทสนทนาเดิม (เรียก AI, เสียง, คิวประกาศ, ลำดับความสำคัญ) ตอนนี้ไม่สั่งอวตารหรือกล้องตรง ๆ แล้ว ทุกอย่างผ่าน Event ทำให้ 3 Controller เปลี่ยน/ทดสอบแยกกันได้

**การตรวจผู้เข้าชมซ้ำ (`VISITOR_RETURNED`):** ถ้า Session ใหม่เริ่มภายในช่วงคูลดาวน์การทักทาย (`VORA_GREETING_COOLDOWN`) หลังคนก่อนหน้าออกไป ถือว่า "คนเดิมเดินกลับมา" จะไม่ทักซ้ำ — ใช้ช่วงเวลาเท่านั้น ไม่ใช้การจดจำใบหน้า จึงแยกไม่ได้ว่าเป็นคนเดิมจริงหรือคนใหม่ที่เข้ามาเร็ว (ข้อจำกัดที่ตั้งใจ เพื่อความเป็นส่วนตัว)

### 7.2 โหมดหน้าจอ

| | Active | Idle (Avatar Focus) |
|---|---|---|
| เข้าเมื่อ | แตะ/ขยับเมาส์/พิมพ์/ท่ามือ/ชูป้าย | ว่างครบ `ui.idleAfterMs` (15 วิ) หรือกด "โหมดหน้าจอว่าง" ในเครื่องมือ |
| ไม่เข้า Idle ระหว่าง | — | กำลังฟัง/คิด/ตอบผู้ใช้, มีหน้าต่างเปิด, ลิ้นชักข้อมูลเปิด, กำลังพิมพ์ |
| แสดง | Header, เมนูซ้าย, QR, แผงสนทนา, สถานะระบบ, แถบพิมพ์, ปุ่มกล้อง/ท่าทาง/เครื่องมือ | อวตารขนาดใหญ่, วงแหวน+พื้น, แสงรอบตัว, ข้อความแนะนำมุมขวาล่าง, กล่องคำพูดเมื่อพูด |
| อวตาร | ขนาดปกติ | ×1.4 ตามค่า `ui.focusScale` ลดอัตโนมัติถ้าจอไม่พอ (จริง: 1.398 ที่ 1366×768, 1.388 ที่ 1600×900, 1.378 ที่ 1920×1080) กึ่งกลางจอ |
| เบื้องหลัง | กล้อง MediaPipe AI WebSocket หุ่นยนต์ ทำงานตลอด | **เหมือนกันทุกอย่าง** — เปลี่ยนเฉพาะ class/transform บนหน้าจอ |

วิธีขยาย: `transform: translate() scale()` ที่เวทีทั้งก้อน (อวตาร วงแหวน พื้น ขยายพร้อมกัน) จุดหมุนอยู่ที่กึ่งกลางตัวอวตาร คำนวณจาก `offsetLeft/Top` ซึ่งไม่ถูกผลของ transform จึงย่อกลับได้ตรงตำแหน่งเดิม 0 px — SVG/viewBox ไม่ถูกแตะ, Transition 700 ms, แผงต่าง ๆ เลื่อนออก/เข้าทางขอบจอของตัวเองแบบเหลื่อมเวลา, รองรับ `prefers-reduced-motion`

ค่าปรับได้ใน `kiosk-config.js` → `ui`: `idleAfterMs`, `idleHint`, `focusScale`, `focusFit`

- เครื่องทดสอบไม่มี GPU: MediaPipe ใช้ CPU ได้ประมาณ 2 รอบ/วินาที และทำให้ Animation ช้ากว่าจริง (transition 0.7 วิ ใช้เวลาจริง ~1.6 วิ) ผลเทียบ Idle กับ Active จึงวัดเป็น "อัตราส่วน" — บนเครื่องที่มีการ์ดจอ MediaPipe จะเร็วกว่านี้มาก ควรดูความลื่นของการขยายอวตารบนเครื่องจริงอีกครั้ง
- ความลื่นของ Animation วัดจาก "ไม่มี transition ค้าง/ซ้อน" ไม่ได้วัด FPS จริงด้วยตา
